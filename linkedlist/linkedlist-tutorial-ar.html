هيكل بيانات القائمة المرتبطة (Linked List)

CPCS 204 - هياكل البيانات 1

لماذا نحتاج إلى القوائم المرتبطة (Linked Lists) وكيف تعمل

الجزء الأول: لماذا نحتاج إلى القوائم المرتبطة (Linked Lists)؟

قبل أن نتعلم القوائم المرتبطة، يجب أولاً أن نفهم المشكلة التي تحلها. ولنفعل ذلك، دعونا نراجع ما تعرفه مسبقًا: المصفوفات (Arrays).

لنبدأ بالمصفوفات

أنت تعلم مسبقًا أن المصفوفة تخزّن العناصر (Elements) في مواقع ذاكرة متجاورة (Contiguous Memory) أي متتالية. دعونا نتخيل مصفوفة مكوّنة من 5 أعداد صحيحة:

مصفوفة من 5 عناصر في الذاكرة (Memory)

Array:
10 1000
20 1004
30 1008
40 1012
50 1016

لاحظ: كل عنصر يبعد عن الذي يليه 4 بايتات بالضبط (حجم العدد الصحيح). عناوين الذاكرة متتالية!

سؤال: إذا أنشأنا هذه المصفوفة بخمسة عناصر، فهل يمكننا توسيعها لإضافة عناصر أخرى (مثل عنصر سادس)؟
الإجابة: لا! المصفوفة لها حجم ثابت (Fixed Size). فبمجرد إنشائها، لا يمكن توسيعها.

ولكن لماذا حجم المصفوفة ثابت؟

حجم المصفوفة ثابت لأنها يجب أن تستخدم مواقع ذاكرة متجاورة. ولكن لماذا الذاكرة المتجاورة بهذه الأهمية؟

فائدة الذاكرة المتجاورة

عندما تُخزَّن العناصر بشكل متتالٍ، يستطيع المعالج الوصول إلى أي عنصر فورًا باستخدام هذه الصيغة البسيطة:

Element Address = Base Address + (Index × Element Size)

مثال: لإيجاد العنصر عند الفهرس (Index) رقم 3:

Address = 1000 + (3 × 4) = 1000 + 12 = 1012

المعالج يسأل وحدة إدارة الذاكرة (MMU) مرة واحدة فقط عن العنوان الأساسي، ثم يستخدم عملية حسابية بسيطة (الإزاحة) لإيجاد أي عنصر. يُسمى هذا الوصول العشوائي O(1) - وهو سريع بشكل مذهل!

مواقع الذاكرة التالية (1020، 1024...) مشغولة ببرنامج آخر!

فهم أساسي

الذاكرة (RAM) ليست لبرنامجك وحده. برامج كثيرة تعمل في الوقت نفسه وتتشارك الذاكرة ذاتها. المواقع التي تلي مصفوفتك مباشرة قد تكون مستخدمة من قِبل:

  • بيانات برنامج آخر
  • نظام التشغيل
  • مصفوفة أخرى في برنامجك نفسه

وبما أننا لا نستطيع أن نضمن أن المواقع التالية خالية، فإننا لا نستطيع توسيع المصفوفة!

ولكن ماذا لو حجزنا كتلة جديدة من الذاكرة غير متجاورة مع مصفوفتنا؟

ذاكرة غير متجاورة - المشكلة

المصفوفة الأصلية:
10 1000
20 1004
30 1008
40 1012
50 1016
الكتلة الجديدة: ... فجوة في الذاكرة ...
60 2000

المشكلة: العنوان 2000 ليس عند الإزاحة 5 من العنوان 1000!
الصيغة 1000 + (5 × 4) = 1020 تعطي عنوانًا خاطئًا!
نخسر ميزة الوصول العشوائي O(1)!

الخلاصة: إذا لم تكن الذاكرة متجاورة، لا يمكننا استخدام صيغة الإزاحة. سيحتاج المعالج إلى البحث عن مكان تخزين كل عنصر، مما يجعل الوصول بطيئًا جدًا. وهذا يهدم الغرض الأساسي من المصفوفات!

البديل: "التبديل مع القرص" (Disk Swap)

قد يقترح أحد الطلاب: "لماذا لا نحفظ المصفوفة القديمة على القرص الصلب، ثم ننشئ المصفوفة الجديدة الأكبر، ثم ننسخ البيانات مرة أخرى؟"

نعم، هذا ممكن تقنيًا، ولكن...

  • القراءة والكتابة على القرص الصلب أبطأ بـ 1000 مرة من ذاكرة الوصول العشوائي
  • كتابة 1 GB على القرص تستغرق وقتًا كبيرًا
  • قراءة 1 GB مرة أخرى تستغرق وقتًا كبيرًا
  • هذا سيجعل عملية "إضافة" بسيطة تستغرق ثوانيَ أو دقائق!

هذا الحل غير عملي لمعظم التطبيقات.

نحتاج إلى حل أفضل!

هذه المشاكل في المصفوفات دفعت المطورين إلى التفكير: هل هناك طريقة لربط البيانات معًا دون الحاجة إلى ذاكرة متجاورة؟

دعونا نستكشف هذه الفكرة باستخدام شيء تعرفه مسبقًا من البرمجة كائنية التوجه (OOP)...

الجزء 3: لنبنِ الفكرة معاً

أنتم تعرفون بالفعل البرمجة كائنية التوجه (OOP)، وتعرفون كيف تنشئون الأصناف (Class) والكائنات (Object). دعوني أريكم شيئاً مثيراً للاهتمام سيساعدنا على حل مشكلة المصفوفة.

الخطوة 1: صنف Student بسيط

لنبدأ بصنفٍ بسيط تعرفونه جيداً:

Student.java - النسخة البسيطة (Simple Version)
public class Student {
    String name;
    int age;

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}

والآن لننشئ كائن طالب:

إنشاء كائن طالب (Student Object)
Student s1 = new Student("Ahmed", 20);

ماذا يحدث في الذاكرة (Memory)

s1
(مرجع)
→
Student Object
name: "Ahmed"
age: 20

المتغير s1 يحمل مرجعاً (Reference) (عنواناً في الذاكرة) يشير إلى كائن Student.

الخطوة 2: ماذا لو أضفنا مرجعاً إلى طالب آخر؟

والآن، هنا يأتي الجزء المثير للاهتمام. ماذا لو أضفنا داخل الصنف Student متغيراً يمكنه أن يحمل مرجعاً إلى كائن Student آخر؟
Student.java - مع مرجع (Reference) إلى طالب آخر
public class Student {
    String name;
    int age;
    Student nextStudent;  // Reference to another Student!

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
        this.nextStudent = null;  // Initially points to nothing
    }
}

لاحظوا: أضفنا Student nextStudent - وهذا متغير من النوع Student يمكنه أن يحمل مرجعاً إلى كائن Student آخر!

الخطوة 3: لننشئ طالبين ونربطهما معاً

// Create first student

// Create second student
Student s2 = new Student("Sara", 22);

// Link them: s1's nextStudent points to s2
s1.nextStudent = s2;

اكتشاف مذهل!

يمكننا الاستمرار في إضافة الطلاب ما دامت لدينا ذاكرة متاحة! فلا حاجة إلى:

  • التصريح بحجمٍ ثابت

كل طالب جديد يمكن إنشاؤه في أي مكان في الذاكرة - وكل ما نفعله هو ربطه بالسلسلة!

الخطوة 5: كيف نصل إلى هؤلاء الطلاب؟

سؤال جيد! لنفترض أننا نريد طباعة أسماء جميع الطلاب. كيف نصل إليهم؟

الطريقة المباشرة (باستخدام صيغة النقطة Dot Notation)

الوصول إلى كل طالب مباشرة (Direct Access)
// Access first student (Ahmed)
System.out.println(s1.name);  // Output: Ahmed

// Access second student (Sara)
System.out.println(s1.nextStudent.name);  // Output: Sara

// Access third student (Omar)
System.out.println(s1.nextStudent.nextStudent.name);  // Output: Omar

// Access fourth student (Fatima)
System.out.println(s1.nextStudent.nextStudent.nextStudent.name);  // Output: Fatima

// Access fifth student (Ali)
System.out.println(s1.nextStudent.nextStudent.nextStudent.nextStudent.name);  // Output: Ali
لحظة... هذه الطريقة تعمل، ولكن ماذا لو كان لدينا مليون طالب؟ هل سنكتب .nextStudent مليون مرة؟! هذا مستحيل!
ملاحظة ممتازة! أنتم محقون تماماً. نحتاج إلى طريقة أذكى. لنستخدم حلقة تكرار!

الطريقة الذكية (باستخدام حلقة تكرار Loop)

الاجتياز باستخدام حلقة تكرار (Traversing with a Loop)
// Create a temporary variable to "walk" through the chain
Student current = s1;  // Start at the first student

// Keep going while there is a student to visit
while (current != null) {
    // Print current student's info
    System.out.println("Name: " + current.name + ", Age: " + current.age);

    // Move to the next student
    current = current.nextStudent;
}

/* Output:
   Name: Ahmed, Age: 20
   Name: Sara, Age: 22
   Name: Omar, Age: 19
   Name: Fatima, Age: 21
   Name: Ali, Age: 23
*/

الجزء الرابع: إنشاء هيكل بيانات (Data Structure) قابل لإعادة الاستخدام

ما بنيناه يعمل بشكل رائع! لكن دعوني أسألكم سؤالًا...
سؤال: ماذا لو احتجنا غدًا إلى ربط كائنات Car؟ أو كائنات Product؟ أو كائنات Employee؟ هل يجب أن نضيف متغير nextCar إلى الصنف Car؟ ومتغير nextProduct إلى الصنف Product؟

مشكلات أسلوبنا الحالي

  • علينا أن نعدِّل كل صنف (Class) نريد ربطه
  • إضافة nextStudent وnextCar وغيرهما إلى كل صنف ليست ممارسة جيدة
  • منطق الربط أصبح مختلطًا مع صنف البيانات
  • علينا أن نعيد كتابة كود الاجتياز لكل نوع
لماذا لا ننشئ هيكل بيانات قابلًا لإعادة الاستخدام يمكنه استيعاب أي نوع من الكائنات (Object)؟ لنسمِّه... القائمة المرتبطة (Linked List)!

مفهوم القائمة المرتبطة

ما هي القائمة المرتبطة؟

القائمة المرتبطة (Linked List) هي هيكل بيانات يتكون من:

  1. العقد (Nodes) - حاويات تحمل البيانات وترتبط بعضها ببعض
  2. صنف تحكم - يدير العقد (الإضافة، الإزالة، البحث، وغير ذلك)

العقدة (Node): حاوية شاملة

بدلًا من إضافة مرجع (Reference) باسم "next" إلى كل صنف (Student وCar وProduct...)، ننشئ حاوية (Container) منفصلة تسمى العقدة (Node):

مفهوم العقدة

للعقدة جزآن:

DATA
(أي كائن)
NEXT
(مرجع)

DATA: مثل "عربة" أو "صندوق" - يحمل أي كائن (Student، Car، Integer، أي شيء!)
NEXT: يشير إلى العقدة التالية في السلسلة

تخيَّلها كقطار

كل عربة قطار (عقدة) تحتوي على:

  • منطقة شحن (DATA) - حيث تضع ما تريد نقله
  • وصلة ربط (NEXT) - تتصل بعربة القطار التالية

عربات القطار لا يهمها ما بداخلها - هي فقط تحمل وتتصل!

صنف التحكم: LinkedList

نحتاج أيضًا إلى صنف تحكم يدير جميع العقد. هذا الصنف مسؤول عن:

الإضافة
إضافة عقد جديدة
الإزالة
الحذف (Delete) للعقد
الإدراج (Insert)
الإدراج في موضع محدد
البحث
إيجاد العناصر
الاجتياز
زيارة جميع العقد

نظرة عامة على البنية

LinkedList (Control Class)
│
├── head (reference to first Node)
│
└── Node (Inner Class)
    ├── data (the actual object)
    └── next (reference to next Node)
والآن لنبنِ هذا خطوة بخطوة! سنبدأ ببساطة ثم نضيف مزيدًا من الميزات تدريجيًا.

الخطوة 1: إنشاء الصنف Node (بأسلوب الأنواع المُعمَّمة)

أولًا، لننشئ الصنف Node الخاص بنا. سنجعله مُعمَّمًا (Generic) باستخدام <T> ليتمكن من تخزين أي نوع من الكائنات - Student أو Car أو Product أو Integer أو أي شيء آخر!

الصنف العقدة (Node Class) - مُعمَّم (Generic)
/**
 * Node class - A container that holds data and links to the next node.
 * Think of it as a "train car" that carries cargo and connects to the next car.
 *
 * <T> is a "type parameter" - it means "any type"
 * When we create a Node, we specify what type T is (e.g., Student, Integer, etc.)
 */
class Node<T> {
    // The data this node carries (the "cargo")
    // T means it can be ANY type: Student, Car, Integer, String, etc.
    T data;

    // Reference to the next node (the "coupler")
    Node<T> next;

    // Constructor: Create a node with given data
    public Node(T data) {
        this.data = data;
        this.next = null;  // Initially not connected to anything
    }
}

ما هو <T>؟

يسمى <T> معامل النوع (أو النوع المُعمَّم من الأنواع المُعمَّمة (Generics)). إنه مثل عنصر نائب يقول "أستطيع حمل أي نوع". وعندما تنشئ عقدة، فإنك تحدد ما هو T فعليًا:

  • Node<Student> - عقدة تحمل كائنات Student
  • Node<Integer> - عقدة تحمل كائنات Integer
  • Node<Car> - عقدة تحمل كائنات Car
  • Node<String> - عقدة تحمل كائنات String

هذه هي قوة الأنواع المُعمَّمة - صنف واحد يعمل مع جميع الأنواع!

الخطوة 2: إنشاء صنف التحكم LinkedList (بأسلوب الأنواع المُعمَّمة)

الصنف LinkedList - البنية الأساسية (LinkedList Class - Generic)
/**
 * LinkedList class - Controls and manages a chain of nodes.
 * Responsible for adding, removing, and traversing the list.
 *
 * <T> is the type parameter - this list can hold any type of object!
 */
public class LinkedList<T> {

    // Reference to the first node (we call it "head")
    // This is our entry point to the entire list
    private Node<T> head;

    // Constructor: Create an empty linked list
    public LinkedList() {
        this.head = null;  // Empty list = no head
    }

    // Check if the list is empty
    public boolean isEmpty() {
        return head == null;
    }

    // We will add more methods here...
}

كيف نستخدم LinkedList المُعمَّمة

عند إنشاء LinkedList، فإنك تحدد النوع الذي ستحمله:

دالة addFirst()
/**
 * Adds a new node at the BEGINNING of the list.
 * Time Complexity: O(1) - Always constant time!
 *
 * @param data The object to add (can be any type: Student, Car, Integer, etc.)
 */
public void addFirst(T data) {
    // Step 1: Create a new node
    Node<T> newNode = new Node<>(data);

    // Step 2: New node's next points to current head
    newNode.next = head;

    // Step 3: Head now points to new node
    head = newNode;
}

الخطوة 4: طباعة القائمة (Traversal)

لنضف الآن دالة لطباعة (Print) جميع العناصر - وهذه هي طريقة الاجتياز (Traversal) للقائمة.

دالة printList()
/**
 * Prints all elements in the list.
 * Time Complexity: O(n) - Must visit every node
 */
public void printList() {
    // Handle empty list
    if (head == null) {
        System.out.println("List is empty!");
        return;
    }

    // Start from the head
    Node<T> current = head;

    System.out.print("List: ");

    // Traverse until we reach the end (null)
    while (current != null) {
        // Print current node's data
        System.out.print(current.data);

        // Add arrow if not the last node
        if (current.next != null) {
            System.out.print(" -> ");
        }

        // Move to the next node
        current = current.next;
    }

    System.out.println(" -> null");
}

دالة addLast()
/**
 * Adds a new node at the END of the list.
 * Time Complexity: O(n) - Must traverse to the end
 *
 * @param data The object to add (can be any type)
 */
public void addLast(T data) {
    // Step 1: Create a new node
    Node<T> newNode = new Node<>(data);

    // Step 2: If list is empty, new node becomes head
    if (head == null) {
        head = newNode;
        return;
    }

    // Step 3: Traverse to find the last node
    Node<T> current = head;
    while (current.next != null) {
        current = current.next;
    }

    // Step 4: Link the last node to the new node
    current.next = newNode;
}

دالة addAfter()
/**
 * Adds a new node AFTER a node containing the target object.
 * Time Complexity: O(n) - Must search for the target
 *
 * @param target The object to search for
 * @param data The object for the new node
 * @return true if successful, false if target not found
 */
public boolean addAfter(T target, T data) {
    // Search for the target node
    Node<T> current = head;

    while (current != null) {
        // Use .equals() to compare objects (not == which compares references)
        if (current.data.equals(target)) {
            // Found it! Create new node
            Node<T> newNode = new Node<>(data);

            // New node points to what target was pointing to
            newNode.next = current.next;

            // Target now points to new node
            current.next = newNode;

            return true;
        }
        current = current.next;
    }

    // Target not found
    System.out.println("Object not found in the list!");
    return false;
}

الخطوة 9: حذف العقدة الأخيرة (deleteLast)

دالة deleteLast()
/**
 * Deletes the LAST node from the list.
 * Time Complexity: O(n) - Must traverse to second-to-last node
 *
 * @return The deleted object, or null if list is empty
 */
public T deleteLast() {
    // Check if list is empty
    if (head == null) {
        System.out.println("List is empty! Nothing to delete.");
        return null;
    }

    // If only one node, delete it
    if (head.next == null) {
        T deletedData = head.data;
        head = null;
        return deletedData;
    }

    // Traverse to find second-to-last node
    Node<T> current = head;
    while (current.next.next != null) {
        current = current.next;
    }

    // Save the last node's data
    T deletedData = current.next.data;

    // Remove the last node
    current.next = null;

    return deletedData;
}

دالة deleteByValue()
/**
 * Deletes the first node containing the specified object.
 * Time Complexity: O(n) - Must search for the object
 *
 * @param value The object to delete
 * @return true if deleted, false if not found
 */
public boolean deleteByValue(T value) {
    // Check if list is empty
    if (head == null) {
        System.out.println("List is empty!");
        return false;
    }

    // If head contains the value
    if (head.data.equals(value)) {
        head = head.next;
        return true;
    }

    // Search for the node BEFORE the one to delete
    Node<T> current = head;
    while (current.next != null) {
        if (current.next.data.equals(value)) {
            // Skip over the node to delete
            current.next = current.next.next;
            return true;
        }
        current = current.next;
    }

    // Value not found
    System.out.println("Object not found!");
    return false;
}

الجزء 6: التنفيذ الكامل للقائمة المرتبطة المُعمَّمة (Generic LinkedList)

فيما يلي الصنف الكامل للقائمة المرتبطة (Linked List) بالأنواع المُعمَّمة (Generics) الذي يمكنه تخزين أي نوع من الكائنات:

الشيفرة الكاملة (LinkedList.java - Generic)
/**
 * Complete Generic Singly Linked List Implementation
 * CPCS 204 - Data Structures I
 *
 * This linked list can store ANY type of object: Student, Car, Integer, String, etc.
 * The type is specified when creating the list using <T>
 */
public class LinkedList<T> {

    // ==================== Inner Node Class ====================
    /**
     * Node: A generic container that holds data of type T and links to the next node.
     */
    private class Node {
        T data;           // The data stored in this node (any type!)
        Node next;        // Reference to the next node

        Node(T data) {
            this.data = data;
            this.next = null;
        }
    }

    // ==================== LinkedList Properties ====================
    private Node head;  // Reference to the first node

    // ==================== Constructor ====================
    public LinkedList() {
        this.head = null;
    }

    // ==================== Basic Operations ====================

    /** Check if the list is empty */
    public boolean isEmpty() {
        return head == null;
    }

    /** Get the size of the list - O(n) */
    public int size() {
        int count = 0;
        Node current = head;
        while (current != null) {
            count++;
            current = current.next;
        }
        return count;
    }

    // ==================== Insertion Operations ====================

    /** Add at the beginning - O(1) */
    public void addFirst(T data) {
        Node newNode = new Node(data);
        newNode.next = head;
        head = newNode;
    }

    /** Add at the end - O(n) */
    public void addLast(T data) {
        Node newNode = new Node(data);

        if (head == null) {
            head = newNode;
            return;
        }

        Node current = head;
        while (current.next != null) {
            current = current.next;
        }
        current.next = newNode;
    }

    /** Add after a specific object - O(n) */
    public boolean addAfter(T target, T data) {
        Node current = head;

        while (current != null) {
            if (current.data.equals(target)) {
                Node newNode = new Node(data);
                newNode.next = current.next;
                current.next = newNode;
                return true;
            }
            current = current.next;
        }
        return false;
    }

    // ==================== Deletion Operations ====================

    /** Delete the first node - O(1) */
    public T deleteFirst() {
        if (head == null) {
            System.out.println("List is empty!");
            return null;
        }
        T data = head.data;
        head = head.next;
        return data;
    }

    /** Delete the last node - O(n) */
    public T deleteLast() {
        if (head == null) {
            System.out.println("List is empty!");
            return null;
        }

        if (head.next == null) {
            T data = head.data;
            head = null;
            return data;
        }

        Node current = head;
        while (current.next.next != null) {
            current = current.next;
        }
        T data = current.next.data;
        current.next = null;
        return data;
    }

    /** Delete by object - O(n) */
    public boolean deleteByValue(T value) {
        if (head == null) {
            return false;
        }

        if (head.data.equals(value)) {
            head = head.next;
            return true;
        }

        Node current = head;
        while (current.next != null) {
            if (current.next.data.equals(value)) {
                current.next = current.next.next;
                return true;
            }
            current = current.next;
        }
        return false;
    }

    // ==================== Search Operations ====================

    /** Check if object exists - O(n) */
    public boolean contains(T value) {
        Node current = head;
        while (current != null) {
            if (current.data.equals(value)) {
                return true;
            }
            current = current.next;
        }
        return false;
    }

    /** Get object at index - O(n) */
    public T get(int index) {
        if (index < 0) {
            return null;
        }

        Node current = head;
        int count = 0;

        while (current != null) {
            if (count == index) {
                return current.data;
            }
            count++;
            current = current.next;
        }
        return null;  // Index out of bounds
    }

    // ==================== Display ====================

    /** Print the entire list - O(n) */
    public void printList() {
        if (head == null) {
            System.out.println("List is empty!");
            return;
        }

        System.out.print("List: ");
        Node current = head;
        while (current != null) {
            System.out.print(current.data);
            if (current.next != null) {
                System.out.print(" -> ");
            }
            current = current.next;
        }
        System.out.println(" -> null");
    }
}

class Student {
    String name;
    int age;

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // toString() is called when we print the object
    @Override
    public String toString() {
        return name + "(" + age + ")";
    }

    // equals() is used for comparison in contains(), deleteByValue(), etc.
    @Override
    public boolean equals(Object obj) {
        if (obj instanceof Student) {
            Student other = (Student) obj;
            return this.name.equals(other.name) && this.age == other.age;
        }
        return false;
    }
}

مهم: الدالتان toString() و equals()

عند استخدام LinkedList مع كائنات خاصة (مثل Student)، تأكد من إعادة تعريف (Override) الدالتين:

  • toString() - لكي يُطبع الكائن بشكل واضح ومقروء
  • equals() - لكي تعمل دوال المقارنة (contains، deleteByValue، addAfter) بشكل صحيح

الجزء 7: الملخص

ماذا تعلمنا

  1. المصفوفات ثابتة الحجم لأنها تحتاج إلى ذاكرة متجاورة لتحقيق الوصول بزمن O(1)
  2. تجزئة الذاكرة قد تمنع توسيع المصفوفة حتى مع وجود مساحة حرة
  3. مفاهيم البرمجة الكائنية (كائنات تحمل مراجع) يمكنها ربط البيانات ببعضها
  4. القائمة المرتبطة (Linked List) هي بنية بيانات قابلة لإعادة الاستخدام مبنية على هذه الفكرة
  5. العقدة (Node) هي حاوية مُعمَّمة تحمل بيانات من النوع T ومرجعًا إلى العقدة التالية next
  6. الأنواع المُعمَّمة (Generics) (<T>) تسمح للقائمة بتخزين أي نوع من الكائنات
  7. صنف التحكم يدير جميع العمليات (الإضافة، الحذف، البحث، وغيرها)

ملخص التعقيد الزمني (Time Complexity)

addLast() O(n) يجب الاجتياز حتى نهاية القائمة
addAfter() O(n) يجب البحث عن العنصر الهدف
deleteFirst() O(1) يكفي تغيير مؤشر head فقط
deleteLast() O(n) يجب الوصول إلى العقدة قبل الأخيرة
deleteByValue() O(n) يجب البحث عن القيمة
contains() O(n) يجب البحث في القائمة
get(index) O(n) يجب الاجتياز حتى الموقع المطلوب
size() O(n) يجب عدّ جميع العقد
