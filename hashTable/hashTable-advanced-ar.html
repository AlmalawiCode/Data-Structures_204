🔄 محاكي إعادة التجزئة (إعادة الهيكلة)

ما هي إعادة التجزئة؟

عندما يمتلئ جدول التجزئة (Hash Table) أكثر من اللازم، يتراجع أداؤه. تقوم إعادة التجزئة (Rehashing)، وتُسمّى أيضًا إعادة الهيكلة (Restructuring)، بإنشاء جدول جديد أكبر ثم إعادة إدخال جميع العناصر فيه.

  • معامل التحميل (Load Factor) (α) = عدد العناصر / حجم الجدول
  • عندما يتجاوز α حدًّا معيّنًا (عادةً 0.7)، نُعيد التجزئة
  • يكون حجم الجدول الجديد عادةً 2 × الحجم القديم (العدد الأولي التالي)
  • تُعاد تجزئة جميع العناصر باستخدام حجم الجدول الجديد

معامل التحميل (α) = n / m
0 / 7 = 0.00
الحدّ: 0.7

🪣 محاكي التجزئة بالدلاء

ما هي التجزئة بالدلاء؟

في التجزئة بالدلاء (Bucket Hashing)، يُقسَم جدول التجزئة إلى دلاء (Buckets)، يحتوي كلٌّ منها على عدة خانات (Slots).

  • يستطيع كل دلو أن يحمل B من العناصر (حجم الدلو)
  • تحدّد دالة التجزئة (Hash Function) الدلو المستخدَم: bucket = k mod numBuckets
  • داخل الدلو، نبحث خطيًّا عن خانة فارغة (0 → 1 → 2 ...)
  • إذا كان الدلو ممتلئًا، يذهب العنصر إلى منطقة الفائض (Overflow Area)
⚠️ لماذا نحتاج إلى منطقة فائض؟

المشكلة: ماذا يحدث عندما يكون الدلو ممتلئًا تمامًا ونحتاج إلى إدخال عنصر آخر تُعطي تجزئته الدلو نفسه؟

مثال: إذا كان الدلو 3 يتكوّن من 3 خانات ويحتوي مسبقًا على [8, 3, 18]، وأردنا إدخال 38:

  • h(38) = 38 mod 5 = 3 ← الدلو 3
  • لكن الدلو 3 ممتلئ! (جميع خاناته الثلاث مشغولة)
  • لا يمكننا وضع 38 في دلو آخر (فذلك يُفسد دالة التجزئة!)
  • الحل: نخزّن 38 في منطقة فائض منفصلة

منطقة الفائض هي مساحة تخزين احتياطية للعناصر عندما لا يتبقّى مكان في الدلو المخصّص لها. ويُبحث فيها بعد فحص الدلو الرئيسي أثناء عمليات البحث.

📦 هيكل البيانات المستخدَم

تستخدم التجزئة بالدلاء مصفوفة ثنائية الأبعاد (2D Array) (مصفوفة من المصفوفات):

// تعريف في Java
int[][] buckets = new int[numBuckets][bucketSize];
int[] overflow = new int[overflowSize]; // للفائض

// تمثيل المصفوفة ثنائية الأبعاد:
Bucket\Slot 0 1 2 ← فهارس الخانات (أفقيًّا)
0 16 11 —
1 — — —
2 32 — —
3 8 3 18 ← ممتلئ!
4 24 — —
↑
فهارس الدلاء (رأسيًّا)

// مصفوفة الفائض أحادية البعد:
Index: 0 1
Value: 38 23

منطقة الفائض: مصفوفة أحادية البعد (1D Array) منفصلة تُخزَّن فيها العناصر بالتتابع عندما يكون دلوها المستهدَف ممتلئًا تمامًا.

⚠️ الصيغة

فهرس الدلو = h(k) = k mod (عدد الدلاء)

داخل الدلو، أدخِل العنصر في أول خانة فارغة (بحث خطي داخل الدلو).

🔗 محاكي السلاسل المنفصلة

ما هي السلاسل المنفصلة؟

في السلاسل المنفصلة (Separate Chaining)، تحتوي كل خانة في الجدول على قائمة مرتبطة (Linked List) (سلسلة) من العناصر.

  • تحدّد دالة التجزئة السلسلة التي تُستخدَم
  • تُضاف العناصر المتصادمة إلى السلسلة نفسها
  • لا توجد مشكلة فائض؛ إذ يمكن للسلاسل أن تنمو حسب الحاجة
  • يتطلّب البحث اجتياز (Traversal) السلسلة الموجودة عند ذلك الفهرس
📦 هيكل البيانات المستخدَم

تستخدم السلاسل المنفصلة مصفوفة من القوائم المرتبطة:

// تعريف في Java
LinkedList<Integer>[] chains = new LinkedList[tableSize];

// مثال: حجم الجدول = 7
chains[0] → NULL
chains[1] → [22] → [15] → NULL ← تصادمان
chains[2] → NULL
chains[3] → [10] → [31] → [17] → NULL ← 3 عناصر
chains[4] → [4] → NULL
chains[5] → NULL
chains[6] → [28] → NULL

كل فهرس يشير إلى قائمة مرتبطة يمكنها أن تنمو ديناميكيًّا حسب الحاجة!

✅ المزايا
  • معالجة بسيطة للتصادم (Collision)؛ يكفي الإضافة إلى السلسلة
  • لا يصبح الجدول «ممتلئًا» أبدًا
  • الحذف سهل؛ يكفي الإزالة من القائمة المرتبطة
  • يتراجع الأداء تدريجيًّا وبسلاسة مع ازدياد التصادمات
