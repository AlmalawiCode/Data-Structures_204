1. ما هو الطابور؟

التعريف: الطابور (Queue) هيكل بيانات خطي (Linear Data Structure) يخزّن العناصر بشكل تسلسلي، بحيث تتم الإضافة عند أحد طرفيه ويُسمّى المؤخرة (REAR)، ويتم الحذف عند الطرف الآخر ويُسمّى المقدمة (FRONT). ويتّبع الطابور مبدأ FIFO (الداخل أولًا يخرج أولًا - First In, First Out) — أي أن أول عنصر يُضاف هو أول عنصر يُحذف.

موقع الطابور بين هياكل البيانات

تنقسم هياكل البيانات إلى فئتين رئيسيتين:

  • هياكل البيانات الفيزيائية (Physical Data Structures) — هياكل موجودة فعليًا في الذاكرة ولها تمثيل مباشر على مستوى العتاد. أمثلة: المصفوفات (Arrays) والقوائم المرتبطة (Linked Lists).
  • هياكل البيانات المنطقية (Logical Data Structures) — هياكل تُعرّف سلوكًا منطقيًا لتنظيم البيانات والوصول إليها. ولا يمكن بناؤها دون هيكل بيانات فيزيائي تحتها. أمثلة: المكدس (Stack) والطابور والشجرة (Tree) والمخطط (Graph).

الطابور هيكل بيانات منطقي — فهو يصف مفهومًا (سياسة الوصول FIFO)، لكن لكي يخزّن البيانات فعليًا يجب تنفيذه فوق مصفوفة أو قائمة مرتبطة.

الخصائص الأساسية للطابور

  • هيكل بيانات خطي: تُرتَّب العناصر ترتيبًا تسلسليًا
  • الوصول من طرفين: الإضافة عند المؤخرة (REAR)، والحذف من المقدمة (FRONT)
  • سياسة FIFO: الداخل أولًا يخرج أولًا — العنصر الذي انتظر أطول مدة يُخدَم أولًا
  • مؤشّران (Pointers): يتتبّع front العنصر الأول، ويتتبّع rear العنصر الأخير

الطابور مقابل المكدس — الفرق الجوهري

كلٌّ من المكدس والطابور هيكل بيانات خطي ومنطقي. والفرق الحاسم بينهما هو سياسة الوصول (Access Policy):

  • المكدس ← LIFO (الداخل أخيرًا يخرج أولًا - Last In, First Out) — طرف واحد (القمة TOP)
  • الطابور ← FIFO (الداخل أولًا يخرج أولًا) — طرفان (المقدمة FRONT والمؤخرة REAR)

فكّر في الأمر هكذا: المكدس يشبه كومة من الأطباق (تأخذ من الأعلى)، بينما الطابور يشبه صفًّا من الناس (أول شخص في الصف يغادر أولًا).

2. الطابور بوصفه نوعًا مجردًا للبيانات (ADT)

لماذا يُعدّ الطابور نوعًا مجردًا للبيانات؟

الطابور نوع مجرد للبيانات (Abstract Data Type - ADT) لأنه يُعرّف السلوك من خلال مجموعة من العمليات دون أن يحدّد كيف تُنفَّذ هذه العمليات داخليًا. فمستخدم الطابور لا يرى إلا الواجهة (Interface): أدخِل من هنا، وأخرِج من هناك — ولا يحتاج إلى معرفة ما إذا كانت مصفوفة أو قائمة مرتبطة هي المستخدمة في الأسفل.

المنطقي مقابل الفيزيائي — خلاصة

  • الطابور لا يمكن أن يوجد وحده في الذاكرة — فهو مفهوم منطقي.
  • يجب تنفيذه فوق هيكل فيزيائي (مصفوفة أو قائمة مرتبطة).
  • يبقى السلوك (FIFO) نفسه أيًّا كان الهيكل الفيزيائي الذي تختاره.
  • هذا الفصل بين السلوك والتنفيذ هو ما يجعل الطابور نوعًا مجردًا للبيانات (ADT).

سياسة الوصول: FIFO

FIFO = الداخل أولًا يخرج أولًا (First In, First Out)

العنصر الذي أُدخل أولًا هو الذي يُحذف أولًا. وهذه هي القاعدة الأساسية (سياسة الوصول) لكل طابور، بغض النظر عن طريقة تنفيذه.

3. عمليات الطابور

العمليات الأساسية الست للطابور هي:

3.1 enqueue(element) — الإضافة إلى المؤخرة

الغرض: إضافة عنصر إلى مؤخرة (REAR) الطابور — أي الإدخال في الطابور (Enqueue)

تناظر: العملية push() في المكدس

التعقيد الزمني (Time Complexity): O(1) في الطريقتين غير الواقعية والدائرية؛ و O(n) في طريقة الإزاحة (الواقعية)

الخوارزمية — enqueue(element)

  1. تحقّق مما إذا كان الطابور ممتلئًا. إذا كان ممتلئًا ← أبلِغ عن خطأ الفيض (Overflow) وتوقّف.
  2. قدِّم مؤشر المؤخرة rear: rear = rear + 1 (أو rear = (rear+1) % SIZE في الطابور الدائري)
  3. خزّن العنصر في موقع المؤخرة الجديد: queue[rear] = element
  4. إذا كان هذا أول عنصر يُضاف (كانت قيمة front تساوي −1)، فاجعل أيضًا front = 0

3.2 dequeue() — الحذف من المقدمة

الغرض: حذف العنصر الموجود في مقدمة (FRONT) الطابور وإرجاعه — أي الإخراج من الطابور (Dequeue)

تناظر: العملية pop() في المكدس

التعقيد الزمني: O(1) في الطريقتين غير الواقعية والدائرية؛ و O(n) في طريقة الإزاحة

الخوارزمية — dequeue()

  1. تحقّق مما إذا كان الطابور فارغًا. إذا كان فارغًا ← أبلِغ عن خطأ النقص (Underflow) وتوقّف.
  2. احفظ العنصر الموجود في المقدمة: temp = queue[front]
  3. قدِّم مؤشر المقدمة front: front = front + 1 (أو front = (front+1) % SIZE في الطابور الدائري)
  4. إذا كان front > rear فقد أصبح الطابور فارغًا — أعِد ضبط المؤشرين كليهما إلى −1
  5. أرجِع temp

3.3 peek() — الاطّلاع على المقدمة

الغرض: إرجاع العنصر الموجود في المقدمة دون حذفه

تناظر: العملية top() في المكدس

التعقيد الزمني: O(1)

3.4 isEmpty()

الغرض: تُرجع true إذا لم يكن في الطابور أي عنصر

الشرط: front == -1 (أو front > rear في الحالة الخطية)

3.5 isFull()

الغرض: تُرجع true إذا كان الطابور لا يتسع لمزيد من العناصر

الشرط: rear == SIZE - 1 في الطريقتين غير الواقعية/الواقعية؛ و (rear + 1) % SIZE == front في الدائرية

3.6 clear()

الغرض: تفريغ الطابور بإعادة ضبط المؤشرين كليهما

الإجراء: front = rear = -1

العملية الوصف مصفوفة (دائرية) قائمة مرتبطة
enqueue(e) إضافة e عند المؤخرة queue[(rear+1)%N] = e tail.next = newNode
dequeue() حذف عنصر المقدمة وإرجاعه return queue[(front+1)%N] حذف عقدة الرأس (head)
peek() عرض عنصر المقدمة return queue[front] return head.data
isEmpty() هل الطابور فارغ؟ front == -1 head == null
isFull() هل الطابور ممتلئ؟ (rear+1)%N == front لا ينطبق (ديناميكي)
clear() تفريغ الطابور front = rear = -1 head = tail = null

4. التنفيذ باستخدام المصفوفة

بما أن الطابور هيكل بيانات منطقي، فيجب تنفيذه باستخدام هيكل فيزيائي. لنبدأ بـالمصفوفة (Array). نستخدم مصفوفة ثابتة الحجم (مثلًا 5 عناصر) ونحتفظ بمؤشرين من نوع عدد صحيح:

  • front — فهرس (Index) العنصر الأول (الأقدم)؛ يبدأ من −1
  • rear — فهرس العنصر الأخير (الأحدث)؛ يبدأ من −1

عندما تكون قيمة كليهما −1 يكون الطابور فارغًا.

توجد ثلاث استراتيجيات لتنفيذ الطابور باستخدام المصفوفة، ولكلٍّ منها مزايا وعيوب مختلفة:

  1. غير الواقعية (Unrealistic) — بسيطة لكنها تُهدر المساحة
  2. الواقعية (بالإزاحة - Shifting) — تستخدم كل المساحة لكنها بطيئة
  3. الدائرية (Circular) — تجمع أفضل ما في الطريقتين باستخدام حساب باقي القسمة (Modulo) ✓

4.1 الاستراتيجية 1 — غير الواقعية (الخطية البسيطة)

في هذه الاستراتيجية نقدّم كلا المؤشرين ببساطة كلما أُضيفت العناصر أو حُذفت، ولا نزيح العناصر إلى الخلف أبدًا. فالمؤشر يتحرك إلى الأمام فقط — ولا يعود إلى البداية أبدًا.

كيف تعمل

  • في البداية: front = rear = −1
  • enqueue: زِد rear بمقدار واحد، وضع العنصر في queue[rear]
  • dequeue: احفظ queue[front]، ثم زِد front بمقدار واحد
  • isFull: rear == SIZE − 1

المشكلة — لماذا تُسمّى «غير واقعية»

تخيّل طابورًا حجمه 5. أدخلتَ 5 عناصر (الفهارس 0–4)، فأصبح الطابور ممتلئًا (rear = 4). ثم أخرجتَ 3 عناصر (front = 3). منطقيًا أصبحت هناك 3 خانات فارغة (الفهارس 0 و1 و2). لكن الشرط rear == SIZE − 1 ما زال true، لذا يُبلغ الطابور بأنه ممتلئ رغم توفّر 3 مواقع!

هذه المساحة المهدرة لا يمكن استعادتها أبدًا؛ إذ سيرفض الطابور أي إدخال جديد رغم وجود أماكن فارغة. ولهذا تُسمّى هذه الاستراتيجية غير واقعية — فهي غير عملية للاستخدام الحقيقي.

⚠️ عرض تفاعلي — الطابور غير الواقعي

حجم الطابور = 5. أدخِل عناصر وأخرِجها، ثم لاحظ مشكلة المساحة المهدرة.

المقدمة (front): -1
المؤخرة (rear): -1
الحجم (size): 5
الطابور فارغ. ابدأ بإدخال قيمة.

4.2 الاستراتيجية 2 — الواقعية (بالإزاحة)

يلاحظ أحد الطلاب المشكلة السابقة فيقترح: «لماذا لا نزيح جميع العناصر نحو الفهرس 0 بعد كل عملية إخراج؟» هذه هي استراتيجية الإزاحة (Shifting). فبعد حذف عنصر المقدمة يُزاح كل عنصر متبقٍّ موقعًا واحدًا إلى اليسار (نحو الفهرس 0)، ويبقى front دائمًا عند 0.

كيف تعمل الإزاحة

  • قيمة front دائمًا 0
  • dequeue: احذف queue[0]، وأزِح جميع العناصر إلى اليسار (queue[i] = queue[i+1])، ثم أنقِص rear بمقدار واحد
  • لا تُهدر أي مساحة أبدًا — فجميع المواقع الفارغة تكون دائمًا في الطرف الأيمن (نهاية المصفوفة)

الثمن — لماذا تضرّ الإزاحة بالأداء

تتطلب كل عملية إخراج إزاحة جميع العناصر المتبقية موقعًا واحدًا إلى اليسار. فإذا كان في الطابور n عنصرًا، فهذا يعني عملًا بمقدار O(n) لكل عملية إخراج — وليس O(1). وقد يكون ذلك بطيئًا جدًا في الطوابير الكبيرة. تبقى عملية الإدخال O(1)، لكن الإخراج يصبح O(n).

المؤخرة (rear): -1
الحجم (size): 5

4.3 الاستراتيجية 3 — الطابور الدائري (الحل الأفضل)

الطابور الدائري (Circular Queue): بدلًا من التحرك إلى الأمام في خط مستقيم، تُعامَل المصفوفة على أنها دائرة — أي مصفوفة دائرية (Circular Array). فعندما يصل rear إلى الفهرس الأخير يلتفّ عائدًا إلى الفهرس 0 باستخدام عامل باقي القسمة (%). وهذا يقضي على المساحة المهدرة ويُبقي جميع العمليات بتعقيد O(1).

الصيغة الأساسية — حساب باقي القسمة

  • الإدخال (Enqueue): rear = (rear + 1) % SIZE
  • الإخراج (Dequeue): front = (front + 1) % SIZE
  • isEmpty: front == -1 (أو استخدم متغيّر عدّاد count)
  • isFull: (rear + 1) % SIZE == front

يجعل عامل باقي القسمة الفهرس يلتفّ إلى البداية. فإذا كان SIZE = 5 و rear = 4، فإن (4 + 1) % 5 = 0 — أي يقفز rear عائدًا إلى البداية!

حالات مهمة في الطابور الدائري

الحالة الشرط المعنى
طابور فارغ front == -1 لا توجد عناصر؛ يُعاد ضبط المؤشرين إلى −1
طابور ممتلئ (rear + 1) % SIZE == front تُترك خانة واحدة فارغة دائمًا كخانة حارسة (Sentinel) للتمييز بين الامتلاء والفراغ
عنصر واحد front == rear يشير front و rear إلى الخانة نفسها
الالتفاف (Wrap-around) rear = (rear+1) % SIZE يلتفّ rear من الفهرس الأخير عائدًا إلى 0

المقدمة (front): -1

مقارنة بين الاستراتيجيات الثلاث

❌ غير الواقعية

enqueue: O(1)

dequeue: O(1)

المشكلة: تُهدر المساحة — فالمواقع التي تتحرر بالإخراج لا يمكن إعادة استخدامها أبدًا.

⚠️ الواقعية (بالإزاحة)

enqueue: O(1)

dequeue: O(n) — إزاحة جميع العناصر!

المشكلة: لا مساحة مهدرة، لكن الإخراج بطيء في الطوابير الكبيرة.

✓ الدائرية (الأفضل)

enqueue: O(1)

dequeue: O(1)

الميزة: تلتفّ باستخدام باقي القسمة — لا مساحة مهدرة ولا حاجة إلى الإزاحة!

5. التنفيذ بلغة Java

5.1 الطابور الدائري باستخدام المصفوفة

▶ CircularQueue.java — طابور دائري قائم على المصفوفة ▼
public class CircularQueue { private int[] queue; private int front, rear, count, size; // Constructor public CircularQueue(int size) { this.size = size; queue = new int[size]; front = rear = -1; count = 0; } // isEmpty — O(1) public boolean isEmpty() { return count == 0; } // isFull — O(1) public boolean isFull() { return count == size; } // enqueue — Add to REAR — O(1) public void enqueue(int value) { if (isFull()) { System.out.println("Queue Overflow! Cannot enqueue " + value); return; } if (isEmpty()) front = 0; // first element rear = (rear + 1) % size; // wrap rear queue[rear] = value; count++; } // dequeue — Remove from FRONT — O(1) public int dequeue() { if (isEmpty()) { System.out.println("Queue Underflow! Cannot dequeue"); return -1; } int removed = queue[front]; count--; if (isEmpty()) { // queue is now empty front = rear = -1; } else { front = (front + 1) % size; // wrap front } return removed; } // peek — View front element — O(1) public int peek() { if (isEmpty()) { System.out.println("Queue is empty!"); return -1; } return queue[front]; } // clear — Reset queue public void clear() { front = rear = -1; count = 0; } // display contents public void display() { if (isEmpty()) { System.out.println("Queue is empty"); return; } System.out.print("Queue [FRONT→REAR]: "); int i = front; for (int k = 0; k < count; k++) { System.out.print(queue[i] + " "); i = (i + 1) % size; } System.out.println(); } }

5.2 الطابور باستخدام القائمة المرتبطة

▶ LinkedQueue.java — طابور قائم على القائمة المرتبطة ▼
// Node class class Node { int data; Node next; Node(int data) { this.data = data; next = null; } } public class LinkedQueue { private Node front, rear; private int count; public LinkedQueue() { front = rear = null; count = 0; } public boolean isEmpty() { return front == null; } // enqueue — O(1): always insert at tail public void enqueue(int value) { Node newNode = new Node(value); if (isEmpty()) { front = rear = newNode; } else { rear.next = newNode; rear = newNode; } count++; } // dequeue — O(1): always remove from head public int dequeue() { if (isEmpty()) { System.out.println("Queue Underflow!"); return -1; } int removed = front.data; front = front.next; if (front == null) rear = null; // queue is empty count--; return removed; } public int peek() { if (isEmpty()) return -1; return front.data; } }

لماذا يُعدّ التنفيذ بالقائمة المرتبطة سهلًا

مع القائمة المرتبطة لا يوجد مفهوم «الامتلاء» — إذ تنمو القائمة ديناميكيًا حسب الحاجة. فلا مساحة مهدرة، ولا منطق للالتفاف، ولا إزاحة. والثمن هو ذاكرة إضافية لكل عقدة (Node) (المرجع next). وفي معظم الأغراض العملية يُعدّ كلٌّ من التنفيذ بـالمصفوفة الدائرية والتنفيذ بـالقائمة المرتبطة خيارًا ممتازًا.
