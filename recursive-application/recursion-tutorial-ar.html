العودية (Recursion)

هياكل البيانات 1

فهم الدالة العودية (Recursive Method)

1. مقدمة

اليوم يا طلابي سنتعلم شيئًا قد يكون جديدًا عليكم، شيئًا يُسمّى العودية (Recursion) أو الدالة العودية (Recursive Method). لكن قبل أن نقفز إلى هذا المفهوم، أعتقد أننا بحاجة إلى مناقشة أمر مهم أولًا.

قبل أن نتمكن من فهم العودية، نحتاج إلى مراجعة أمر أساسي: كيف تعمل البرامج فعليًا في الذاكرة. وبمجرد أن نفهم ذلك، ستصبح العودية أوضح بكثير.

ما سنتناوله اليوم:
  1. كيف تُنفَّذ البرامج في الذاكرة (مكدس الاستدعاءات Call Stack)
  2. العدّ باستخدام حلقات التكرار (الأسلوب التكراري Iterative)
  3. العدّ بدون حلقات تكرار (دوال متعددة)
  4. فكرة الدالة التي تستدعي نفسها
  5. ما هي العودية (Recursion)؟
  6. التكراري مقابل العودي — مقارنة ومتى نستخدم كلًّا منهما

2. كيف تعمل البرامج في الذاكرة

كما نعلم جميعًا، عندما نكتب برنامجًا ونشغّله، يُحمَّل البرنامج إلى الذاكرة. دعونا نفكر في ذلك بلغة Java.

لنأخذ برنامج Java بسيطًا. لدينا الدالة (Method) main، وبداخلها نستدعي دالة أخرى تُسمّى printing() تطبع "Welcome to Java".

Java - استدعاء دالة بسيط ▼
public class MyProgram { public static void main(String[] args) { printing(); // Call the printing method } public static void printing() { System.out.println("Welcome to Java"); } }

تصوّر مكدس الاستدعاءات (Call Stack)

الآن أريدكم أن تتخيلوا مستطيلًا مفتوحًا من الأعلى. هذا يمثّل مكدس الاستدعاءات (Call Stack) في الذاكرة. عندما تبدأ main() تُوضع في المكدس. وعندما تستدعي main() الدالة printing()، تُوضع الدالة printing() فوق main() في المكدس.
تذكّر: يتبع مكدس الاستدعاءات ترتيب الأخير دخولًا هو الأول خروجًا (LIFO). الدالة الموجودة في القمة تُنفَّذ أولًا، وعندما تنتهي تُزال (Pop) من المكدس، ويعود التنفيذ إلى الدالة التي تحتها.

تحريك: مكدس استدعاء دالة بسيط

تنفيذ الكود

// Program starts
public static void main(...) {
    printing();
}
public static void printing() {
    System.out.println("Welcome to Java");
}

3. العدّ باستخدام حلقة تكرار (Loop)

الآن، لنكتب برنامجًا بسيطًا. أريد العدّ من 1 إلى 5 وطباعة كل رقم. هذا سهل جدًا — نستخدم حلقة for.
Java - العدّ باستخدام حلقة for ▼
public class CountLoop { public static void main(String[] args) { for (int i = 1; i <= 5; i++) { System.out.println("Counter: " + i); } } }

معاينة المخرجات

بسيط وواضح! تكرّر حلقة for جملة الطباعة 5 مرات، مع زيادة i بمقدار 1 في كل مرة. هذا هو الأسلوب التكراري (Iterative) — استخدام بنى التكرار مثل الحلقات.

4. ماذا لو لم نستخدم حلقة تكرار؟

حسنًا يا طلابي، أنتم راضون عن حلقة التكرار. هذا رائع! لكن تخيّلوا الآن... ماذا لو قلت لكم: لا تستخدموا حلقة تكرار. كيف ستعدّون من 1 إلى 5؟
ماذا يمكننا أن نستخدم بدلًا منها يا دكتور؟
دعوني أريكم. ماذا لو أنشأت خمس دوال عدّاد منفصلة؟ كل دالة مسؤولة عن طباعة رقم واحد ثم استدعاء الدالة التالية.
Java - خمس دوال عدّاد منفصلة ▼
public class CountNoLoop { public static void main(String[] args) { int n = 0; counter1(n); // Start with counter1, pass n = 0 } public static void counter1(int n) { n = n + 1; // n becomes 1 counter2(n); // Call counter2 FIRST, pass n = 1 System.out.println("Counter: " + n); // Print AFTER counter2 returns } public static void counter2(int n) { n = n + 1; // n becomes 2 counter3(n); // Call counter3 FIRST, pass n = 2 System.out.println("Counter: " + n); // Print AFTER counter3 returns } public static void counter3(int n) { n = n + 1; // n becomes 3 counter4(n); // Call counter4 FIRST, pass n = 3 System.out.println("Counter: " + n); // Print AFTER counter4 returns } public static void counter4(int n) { n = n + 1; // n becomes 4 counter5(n); // Call counter5 FIRST, pass n = 4 System.out.println("Counter: " + n); // Print AFTER counter5 returns } public static void counter5(int n) { n = n + 1; // n becomes 5 // No more methods to call, so print immediately System.out.println("Counter: " + n); } }

لنتصوّر مكدس الاستدعاءات!

الآن دعوني أريكم ما يحدث في الذاكرة. راقبوا كيف تدخل كل دالة إلى المكدس عند استدعائها، وكيف تخرج جميعها عندما تنتهي.

تحريك: خمس دوال عدّاد على المكدس

ما الذي يحدث

main() تضبط n=0 وتستدعي counter1(0)
counter1(0): تصبح n=1 وتستدعي counter2(1)
counter2(1): تصبح n=2 وتستدعي counter3(2)
counter3(2): تصبح n=3 وتستدعي counter4(3)
counter4(3): تصبح n=4 وتستدعي counter5(4)
counter5(4): تصبح n=5 وتطبع 5 (الأخيرة!)
-- الانحلال (Unwinding): كل دالة تطبع عند إزالتها من المكدس --

لكن ماذا عن 100؟

يا طلابي، نجح هذا جيدًا مع 5 أرقام. لكن ماذا لو طلبت منكم العدّ حتى 100؟ هذا يعني أنكم بحاجة إلى إنشاء 100 دالة منفصلة! counter1(), counter2(), counter3(), ... وصولًا إلى counter100(). هذا غير عملي على الإطلاق!
المشكلة: إنشاء 100 نسخة من الدالة نفسها تقريبًا هو أمر:
  • ممل للغاية وعرضة للأخطاء
  • غير قابل للتوسع — ماذا لو احتجنا إلى 1000؟
  • مخالف لمبادئ البرمجة الجيدة (مبدأ DRY - لا تكرّر نفسك)
إذن يا دكتور، ألا توجد طريقة لأن تكون لدينا دالة واحدة تقوم بالعمل نفسه؟

5. دالة واحدة تستدعي نفسها

سؤال ممتاز! ماذا لو أنشأت نسخة واحدة فقط من دالة العدّاد؟ هذه الدالة الوحيدة تزيد العدّاد بمقدار واحد ثم تستدعي نفسها!
Java - دالة تستدعي نفسها ▼
public class CountRecursive { public static void main(String[] args) { counter(1); // Start counting from 1 } public static void counter(int n) { if (n <= 5) { // Base case: stop when n > 5 counter(n + 1); // Call itself FIRST with n+1 System.out.println("Counter: " + n); // Print AFTER the recursive call returns } } }

لنرَ ذلك في الذاكرة!

الآن دعوني أريكم ما يحدث في الذاكرة. من المهم جدًا أن تروا كيف يعمل هذا. راقبوا بعناية — ستلاحظون شيئًا مشابهًا لدوال العدّاد الخمس، لكن الآن الدالة نفسها هي التي تستدعي نفسها في كل مرة!

تحريك: العدّاد العودي على المكدس

الكود (دالة واحدة!)

public static void counter(int n) {
  if (n <= 5) {
    counter(n + 1); // call FIRST
    println("Counter: "+ n); // print AFTER
  }
}

6. الخطر: لا توقّف!

نعم يا طلابي، هذا رائع! لكن دعوني أسألكم سؤالًا مهمًا جدًا: ماذا يحدث إذا استدعت الدالة نفسها مرات كثيرة جدًا دون أن تتوقف أبدًا؟ ماذا لو أزلنا الشرط if (n <= 5)؟
Java - عودية لا نهائية (خطر!) ▼
public class InfiniteRecursion { public static void main(String[] args) { counter(1); } public static void counter(int n) { System.out.println("Counter: " + n); counter(n + 1); // No stopping condition! // This method will call itself FOREVER! } }

المخرجات

نفدت ذاكرة المكدس! لقد انهار البرنامج.

اضغط "تشغيل" للبدء، ثم انقر "التالي" لترى كيف يملأ كل استدعاء المكدس.
فيض المكدس (Stack Overflow)! بدون شرط توقّف، تستمر الدالة في استدعاء نفسها إلى ما لا نهاية. كل استدعاء يضيف إطارًا جديدًا إلى المكدس. وفي النهاية تنفد ذاكرة المكدس، وينهار البرنامج بخطأ StackOverflowError.
هذا يشبه الحلقة اللانهائية!
  • الحلقة اللانهائية تعمل إلى الأبد لكنها تستخدم مساحة الذاكرة نفسها.
  • العودية اللانهائية تعمل إلى الأبد أيضًا، لكن كل استدعاء يستخدم ذاكرة جديدة على المكدس — لذا فإنها في النهاية تدمّر المكدس وتُسقط البرنامج!

7. ما هي العودية (Recursion)؟

العودية (Recursion) هي أسلوب برمجي تقوم فيه الدالة باستدعاء نفسها لحل مشكلة ما. كل استدعاء يعمل على نسخة أصغر من المشكلة نفسها حتى يصل إلى الحالة الأساسية (Base Case) (وهي شرط تتوقف عنده الدالة عن استدعاء نفسها وتُعيد نتيجة).

الجزءان الأساسيان في العودية

1. الحالة الأساسية (Base Case) - شرط التوقف

هذا هو الشرط الذي يوقف العودية. وبدونه تحصل على عودية لا نهائية وفيض في المكدس!

if (n > 5) return; // STOP!

2. الحالة العودية (Recursive Case) - الاستدعاء الذاتي

هنا تقوم الدالة باستدعاء نفسها بمعاملات معدّلة، متجهةً نحو الحالة الأساسية.

counter(n + 1); // Call itself
الدالة العودية (Recursive Method): دالة تستدعي نفسها، بشكل مباشر أو غير مباشر، لحل مشكلة عن طريق تقسيمها إلى مشكلات فرعية أصغر من النوع نفسه.

8. التكراري (Iterative) مقابل العودي (Recursive)

يا طلابي، الآن وقد فهمنا العودية، يبرز سؤال مهم جدًا: متى نستخدم حلقات التكرار (الأسلوب التكراري) ومتى نستخدم العودية؟ هل يمكننا دائمًا استخدام أي منهما؟
يا دكتور، هل يمكننا استخدام الأسلوب التكراري والعودية معًا للمشكلة نفسها؟
نعم، يمكنكم! كل ما يمكن حله بالتكرار يمكن حله بالعودية، والعكس صحيح. لكن — وهذه "لكن" كبيرة — هناك فروق مهمة.

أيهما أفضل؟

يا دكتور، أيهما أفضل؟ متى نستخدم التكرار ومتى نستخدم العودية؟
يا طلابي، يجب أن تعلموا أن العودية أكثر استهلاكًا للذاكرة. إذا كتبتم الكود بحلقات التكرار، فهو بلا شك أكثر كفاءة من العودية. إذن لماذا نتعلم العودية أصلًا؟
لماذا نتعلم العودية؟

لأن هناك بعض المشكلات التي يكون حلها بحلقات التكرار صعبًا جدًا لكنها تصبح أسهل بكثير مع العودية.

على سبيل المثال:

  • استكشاف أنظمة الملفات — مجلدات داخل مجلدات داخل مجلدات (بعمق غير محدد)
  • هياكل بيانات الشجرة (Tree) — اجتياز العقد بعمق لا يمكن التنبؤ به
  • خوارزميات فرّق تسُد (Divide and Conquer) — تقسيم المشكلات إلى مشكلات فرعية أصغر متطابقة
  • التعريفات الرياضية — المضروب (Factorial)، فيبوناتشي (Fibonacci)، دوال الأس (Power)
اتفاق مهم:
  • كل ما يمكن حله بالتكرار يمكن حله أيضًا بالعودية.
  • كل ما يمكن حله بالعودية يمكن حله أيضًا بالتكرار.
  • لكن أحيانًا، بوصفنا بشرًا ومبرمجين، نفضّل العودية لأنها تجعل بعض المشكلات المعقدة أسهل بكثير في التفكير والبرمجة.
في الدرس القادم، سأقدّم لكم بعض السيناريوهات والمشكلات التي ستحفّزكم لتروا لماذا نفضّل أحيانًا الأسلوب العودي بشدة. سأريكم حالات يصعب جدًا حلها بحلقات التكرار لكنها تصبح أنيقة مع العودية. ترقّبوا!

9. الملخص

ما تعلمناه اليوم

  1. مكدس الاستدعاءات (Call Stack) — عند استدعاء دالة، يُدفع إطار إلى المكدس. وعند عودتها، يُزال الإطار.
  2. الأسلوب التكراري — استخدام حلقات التكرار (for, while) لتكرار عملية ما.
  3. أسلوب الدوال المتعددة — إنشاء دوال متشابهة كثيرة أمر غير عملي وغير قابل للتوسع.
  4. يمكن للدالة أن تستدعي نفسها — هذا هو أساس العودية.
  5. بدون حالة أساسية — تؤدي العودية اللانهائية إلى خطأ StackOverflowError (تُستنفد ذاكرة المكدس).
  6. العودية = الحالة الأساسية + الحالة العودية.
  7. التكرار مقابل العودية — كلاهما يمكنه حل المشكلات نفسها. التكرار أكثر كفاءة في الذاكرة، لكن العودية قد تكون أكثر طبيعية للمشكلات المعقدة مثل الأشجار وأنظمة الملفات.
عمل ممتاز اليوم يا طلابي! تأكدوا من فهم مكدس الاستدعاءات وكيف تعمل العودية في الذاكرة. في الدرس القادم سأريكم أمثلة مشوّقة تتألق فيها العودية حقًا!
