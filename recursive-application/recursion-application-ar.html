تطبيق على العودية (Recursion Application)

هياكل البيانات 1

استكشاف المجلدات — لماذا العودية قوية

1. مقدمة

طلابي الأعزاء، وعدتكم في الدرس السابق أن أعرض لكم مثالًا حقيقيًا تتألق فيه العودية (Recursion) فعلًا. اليوم سأريكم كيف يمكن استخدام العودية لحل مشكلة بطريقة أنيقة. وبعد هذا الدرس ستفهمون لماذا نفضّل أحيانًا العودية على الحلقات التكرارية (Loops).

تخيّل أن لديك مجلدًا (Folder) على حاسوبك. داخل هذا المجلد توجد ملفات ومجلدات فرعية (Subfolders). وداخل تلك المجلدات الفرعية توجد ملفات أخرى ومجلدات فرعية أخرى، وهكذا. نريد أن نكتب برنامج Java يطبع كل ملف ومجلد داخل مجلد جذر (Root) معيّن.

التحدي: عمق المجلدات غير معروف واعتباطي. قد يحتوي المجلد على 0 مجلد فرعي أو 10 مجلدات فرعية، ولكل منها مجلداته الفرعية الخاصة. إلى أي عمق يصل؟ لا نعرف!

3. النسخة الأولى: طباعة مستوى الجذر فقط

لنبدأ ببساطة. سأكتب برنامج Java يفتح المجلد الجذر ويطبع المستوى الأول فقط — أي العناصر الموجودة مباشرة داخل MyProject.
V1 Java - طباعة مستوى الجذر فقط ▼
import java.io.File; public class FolderExplorer { public static void main(String[] args) { File root = new File("MyProject"); File[] items = root.listFiles(); for (File item : items) { System.out.println(item.getName()); } } }

4. النسخة الثانية: استخراج دالة (Method)

لنكن أذكى. بدلًا من كتابة المنطق مباشرة داخل main()، سأنشئ دالة منفصلة باسم printContents(). نمرر مجلدًا إلى هذه الدالة، فتطبع كل ما بداخل ذلك المجلد.
V2 Java - استخدام دالة ▼
import java.io.File; public class FolderExplorer { public static void main(String[] args) { File root = new File("MyProject"); printContents(root); // Pass the root folder } public static void printContents(File folder) { File[] items = folder.listFiles(); for (File item : items) { System.out.println(item.getName()); } } }
جيد! أصبح لدينا الآن دالة تأخذ أي مجلد وتطبع محتوياته. الناتج هو نفسه ناتج النسخة الأولى، لكن الشيفرة أصبحت أفضل تنظيمًا. الدالة قابلة لإعادة الاستخدام — يمكننا استدعاؤها مع أي مجلد.

5. النسخة الثالثة: نسخ متعددة لكل مستوى

والآن، ماذا لو أردت التعمق أكثر؟ فكرة: أستدعي printContents() للجذر، ثم أستدعيها مرة أخرى لكل مجلد فرعي. دعوني أجرّب ذلك يدويًا.
V3 Java - الاستدعاء اليدوي لكل مستوى ▼
import java.io.File; public class FolderExplorer { public static void main(String[] args) { File root = new File("MyProject"); printContents(root); // Level 0: prints README, src, docs, data // Now manually handle level 1: printContents(new File("MyProject/src")); // Level 1 printContents(new File("MyProject/docs")); // Level 1 printContents(new File("MyProject/data")); // Level 1 // Now manually handle level 2: printContents(new File("MyProject/src/utils")); // Level 2 printContents(new File("MyProject/src/models")); // Level 2 printContents(new File("MyProject/docs/images")); // Level 2 // What about level 3? Level 4? Level 5?... } public static void printContents(File folder) { File[] items = folder.listFiles(); for (File item : items) { System.out.println(item.getName()); } } }
المشكلة:
  • اضطررنا إلى كتابة مسار كل مجلد فرعي يدويًا.
  • يجب أن نعرف البنية مسبقًا — لكن ماذا لو لم نكن نعرفها؟
  • ماذا عن المستوى 3 والمستوى 4 والمستوى 5...؟ علينا أن نستمر في كتابة المزيد والمزيد من الاستدعاءات!
  • إذا تغيّرت بنية المجلدات، تعطّلت شيفرتنا.
هذا ليس عمليًا على الإطلاق! هل يمكننا استخدام حلقة تكرارية بدلًا من ذلك يا أستاذ؟
تفكير جيد! لكن هنا يكمن التحدي: كيف تكتب حلقة تكرارية وأنت لا تعرف إلى أي عمق تصل المجلدات؟ قد يحتوي كل مجلد على مجلدات فرعية، وقد تحتوي تلك المجلدات الفرعية على مجلدات فرعية أخرى. العمق اعتباطي. لا تستطيع الحلقة العادية التعامل مع هذا بسهولة لأنك لا تعرف عدد المستويات التي يجب التكرار عليها.
جوهر التحدي: بنية المجلدات ذات عمق اعتباطي وغير معروف. تعمل حلقة for عندما تعرف عدد مرات التكرار. أما هنا فلا نعرف!

6. النسخة الرابعة: الحل العودي

والآن يا طلابي، راقبوا بعناية. ماذا لو عدّلت الدالة printContents() بحيث عندما تجد مجلدًا فرعيًا فإنها تستدعي نفسها مع ذلك المجلد الفرعي؟ لا تحتاج الدالة إلى معرفة عمق البنية. إنها تقول ببساطة: «إذا كان هذا العنصر مجلدًا، فدعني أستكشفه باستدعاء نفسي مرة أخرى».
V4 Java - الحل العودي ▼
import java.io.File; public class FolderExplorer { public static void main(String[] args) { File root = new File("MyProject"); explore(root); } public static void explore(File folder) { System.out.println("[Folder] " + folder.getName()); File[] items = folder.listFiles(); for (File item : items) { if (item.isDirectory()) { explore(item); // RECURSION! Call itself for subfolders } else { System.out.println(" [File] " + item.getName()); } } } }
هذا كل شيء! بضعة أسطر فقط من الشيفرة، وتستطيع الدالة استكشاف أي بنية مجلدات بأي عمق. دعونا نحللها:
  1. تستقبل الدالة مجلدًا.
  2. تطبع اسم المجلد.
  3. تمر في حلقة على كل عنصر داخل المجلد.
  4. إذا كان العنصر ملفًا → تطبعه.
  5. إذا كان العنصر مجلدًا → تستدعي نفسها مع ذلك المجلد (عودية!).

لنشاهدها وهي تعمل!

دعوني الآن أريكم خطوة بخطوة كيف تستكشف هذه الدالة العودية مجلد MyProject بالكامل. راقبوا مكدس الاستدعاءات (Call Stack) والناتج بعناية!

7. لماذا تفوز العودية هنا

طلابي، الآن يمكنكم أن تروا لماذا العودية قوية جدًا لهذا النوع من المشكلات. دعوني ألخّص السبب.

مقارنة الأساليب

الأسلوب هل يتعامل مع عمق غير معروف؟ عدد أسطر الشيفرة
V1: الجذر فقط لا نحو 5 أسطر
V2: دالة (مستوى واحد) لا نحو 8 أسطر
V3: استدعاءات يدوية فقط إذا كنت تعرف البنية يزداد مع العمق!
V4: عودي نعم! بأي عمق! نحو 10 أسطر
الفكرة الجوهرية: العودية مناسبة طبيعيًا عندما تكون للمشكلة بنية متشابهة ذاتيًا (Self-similar) — أي عندما تبدو المشكلة في كل مستوى مثل المشكلة في المستوى التالي. المجلد يحتوي على ملفات ومجلدات فرعية. والمجلد الفرعي يحتوي أيضًا على ملفات ومجلدات فرعية. البنية تكرر نفسها. وهذا بالضبط ما تفعله العودية: تكرر الدالة نفسها على نسخة أصغر من المشكلة.
تذكروا: يمكن حل هذه المشكلة بحلقة تكرارية باستخدام ما يسمى «هيكل بيانات المكدس (Stack)» يدويًا. لكن بالنسبة لنا كمبرمجين، الحل العودي أسهل بكثير في التفكير والكتابة والفهم. فالحاسوب يتولى إدارة مكدس الاستدعاءات نيابة عنا تلقائيًا!

8. الخلاصة

ما تعلمناه اليوم

  1. النسخة الأولى: برنامج بسيط لا يستطيع طباعة سوى المستوى الأول من المجلد.
  2. النسخة الثانية: استخراج دالة يجعل الشيفرة قابلة لإعادة الاستخدام، لكنها ما زالت تتعامل مع مستوى واحد فقط.
  3. النسخة الثالثة: استدعاء الدالة يدويًا لكل مستوى غير عملي عندما يكون العمق غير معروف.
  4. النسخة الرابعة (العودية): الدالة التي تستدعي نفسها عندما تصادف مجلدًا فرعيًا تستطيع استكشاف أي عمق تلقائيًا.
  5. العودية مناسبة طبيعيًا للمشكلات ذات البنية المتشابهة ذاتيًا (الأشجار، المجلدات، البيانات المتداخلة).
  6. قد تكون الحالة الأساسية ضمنية — عندما لا تُجرى استدعاءات عودية أخرى، تتوقف العودية طبيعيًا.
عمل ممتاز يا طلابي! الآن يمكنكم رؤية القوة الحقيقية للعودية. إنها ليست مجرد مفهوم نظري — بل أداة عملية تجعل المشكلات المعقدة بسيطة وأنيقة. في الدروس القادمة سنرى المزيد من الأمثلة مثل المضروب (Factorial) وفيبوناتشي (Fibonacci) واجتياز الأشجار (Tree Traversals)!
