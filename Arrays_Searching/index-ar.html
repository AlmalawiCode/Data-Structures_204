الجزء 1: المصفوفات (Arrays) - تذكير سريع

يُفترض أنك تعرف هذا مسبقًا!

المصفوفات هياكل بيانات أساسية تعلّمتها في مقررات البرمجة. لنراجع سريعًا ما الذي يميّز المصفوفات ولنفهم حدودها.

ما هي المصفوفة؟

المصفوفة مجموعة من العناصر المخزّنة في مواقع ذاكرة متجاورة (Contiguous) أي متتالية. ويمكن الوصول إلى كل عنصر مباشرةً باستخدام فهرسه (Index).

الخصائص الرئيسية للمصفوفات

  • ذاكرة متجاورة (Contiguous Memory): تُخزَّن العناصر واحدًا تلو الآخر في الذاكرة
  • حجم ثابت (Fixed Size): بمجرد إنشائها لا يمكن تغيير حجمها
  • وصول مباشر (Direct Access): يمكن الوصول إلى أي عنصر فورًا باستخدام فهرسه
  • النوع نفسه (Same Type): يجب أن تكون جميع العناصر من نوع البيانات نفسه

ملخص: التعقيد الزمني (Time Complexity) لعمليات المصفوفة

العملية التعقيد الزمني لماذا؟
الإضافة في النهاية O(1) الانتقال مباشرةً إلى الموضع، دون حاجة إلى إزاحة
الإضافة في البداية O(n) يجب إزاحة جميع العناصر الـ n إلى اليمين
الإضافة في المنتصف O(n) يجب إزاحة العناصر الواقعة بعد نقطة الإدراج
الحذف من النهاية O(1) مجرد إزالة، دون حاجة إلى إزاحة
الحذف من البداية O(n) يجب إزاحة جميع العناصر إلى اليسار
الحذف من المنتصف O(n) يجب إزاحة العناصر لملء الفراغ
الوصول عبر الفهرس O(1) وصول مباشر باستخدام حساب العنوان

الجزء 2: ماذا يعني O(1)؟

ربما تتساءل...

نكرّر قول O(1) وO(n)، لكن ماذا يعنيان فعلًا؟

ترميز O الكبير (Big O Notation) - شرح مبسّط

يصف ترميز O الكبير كيف ينمو الزمن (أو المساحة) الذي تحتاجه الخوارزمية مع ازدياد حجم المدخلات.

  • O(1) - زمن ثابت (Constant Time): تستغرق العملية المقدار نفسه من الزمن بغضّ النظر عن كمية البيانات لديك. إنه الأسرع على الإطلاق!
  • O(n) - زمن خطي (Linear Time): ينمو الزمن بالتناسب مع حجم البيانات. ضعف البيانات = ضعف الزمن.
  • O(log2n) - زمن لوغاريتمي (Logarithmic Time): ينمو الزمن ببطء شديد حتى مع ازدياد البيانات بشكل هائل. فعّال جدًا!

تصوّر O(1) - الزمن الثابت

O(1) = «عملية واحدة»

سواء كان لديك 10 عناصر أو 10 ملايين عنصر، فإن O(1) يستغرق الزمن نفسه.

10 عناصر
خطوة واحدة
1,000 عنصر
خطوة واحدة
1,000,000 عنصر
خطوة واحدة

لماذا يكون الوصول إلى المصفوفة O(1)؟

بسبب صيغة حساب العنوان:

عنوان العنصر = العنوان الأساسي + (الفهرس × حجم العنصر)

يستطيع المعالج (CPU) حساب ذلك فورًا، بغضّ النظر عن حجم المصفوفة!

الجزء 3: البحث الخطي

ما هو البحث الخطي؟

البحث الخطي (Linear Search) هو أبسط خوارزميات البحث. تبدأ من البداية وتفحص كل عنصر واحدًا تلو الآخر حتى تجد ما تبحث عنه.

متى نستخدم البحث الخطي؟

يعمل البحث الخطي على أي مصفوفة - مرتبة أو غير مرتبة. إنه بسيط لكنه قد يكون بطيئًا مع مجموعات البيانات الكبيرة.

تحليل التعقيد الزمني

سيناريو أسوأ حالة (Worst Case)

في تحليل الخوارزميات، نأخذ دائمًا أسوأ حالة في الحسبان. بالنسبة للبحث الخطي، تكون أسوأ حالة عندما يكون العنصر المطلوب في آخر المصفوفة تمامًا (أو غير موجود أصلًا).

البحث الخطي = O(n)

شيفرة البحث الخطي

البحث الخطي - تنفيذ بلغة Java
/**
 * Linear Search Algorithm
 * Searches for a target value in an array by checking each element one by one.
 *
 * Time Complexity: O(n) - worst case checks all elements
 * Space Complexity: O(1) - no extra space needed
 *
 * @param arr    The array to search in
 * @param target The value we are looking for
 * @return       The index of target if found, -1 otherwise
 */
public static int linearSearch(int[] arr, int target) {

    // Loop through each element in the array
    for (int i = 0; i < arr.length; i++) {

        // Check if current element matches the target
        if (arr[i] == target) {
            return i;  // Found! Return the index
        }
    }

    // Target not found in the array
    return -1;
}

الجزء 4: البحث الثنائي - الطريقة السريعة!

هل يمكننا أن نتفوّق على البحث الخطي؟

نعم! لكن هناك شرط: يجب أن تكون البيانات مرتبة (Sorted).

ما هو البحث الثنائي؟

البحث الثنائي (Binary Search) خوارزمية من نوع فرّق تسُد (Divide and Conquer). فبدلًا من فحص كل عنصر، فإنها:

  1. تنظر إلى العنصر الأوسط
  2. إذا كان الهدف أصغر، تبحث في النصف الأيسر
  3. إذا كان الهدف أكبر، تبحث في النصف الأيمن
  4. تكرّر ذلك حتى تجده (أو يتبيّن أنه غير موجود)

الشرط الأساسي

البحث الثنائي يعمل فقط على البيانات المرتبة! إذا لم تكن بياناتك مرتبة، فعليك إمّا:

  • أن ترتّبها أولًا (وللفرز كلفته الخاصة)، أو
  • أن تستخدم البحث الخطي بدلًا منه

قوة البحث الثنائي

شيفرة البحث الثنائي

البحث الثنائي - تنفيذ بلغة Java
/**
 * Binary Search Algorithm
 * Searches for a target value in a SORTED array using divide-and-conquer.
 *
 * Time Complexity: O(log₂n) - halves the search space each step
 * Space Complexity: O(1) - no extra space needed
 *
 * IMPORTANT: The array MUST be sorted for this to work!
 *
 * @param arr    The SORTED array to search in
 * @param target The value we are looking for
 * @return       The index of target if found, -1 otherwise
 */
public static int binarySearch(int[] arr, int target) {

    // Initialize low and high pointers
    int low = 0;
    int high = arr.length - 1;

    // Continue searching while the range is valid
    while (low <= high) {

        // Calculate the middle index
        int mid = (low + high) / 2;

        // Check if we found the target
        if (arr[mid] == target) {
            return mid;  // Found! Return the index
        }
        // If target is greater, ignore left half
        else if (arr[mid] < target) {
            low = mid + 1;  // Search in right half
        }
        // If target is smaller, ignore right half
        else {
            high = mid - 1;  // Search in left half
        }
    }

    // Target not found (low > high)
    return -1;
}

تذكّر هذه القواعد:

  • إذا كان الهدف > قيمة mid ← ابحث في اليمين (اجعل low = mid + 1)
  • إذا كان الهدف < قيمة mid ← ابحث في اليسار (اجعل high = mid - 1)
  • إذا كان الهدف = قيمة mid ← وُجد!
  • إذا كان low > high ← غير موجود

الجزء 5: فهم O(log2n)

من أين يأتي log2n؟

لنفهم رياضيًا لماذا يكون التعقيد الزمني للبحث الثنائي O(log2n). الأساس هو 2 لأننا نقسم على 2 (ثنائي = جزآن) في كل خطوة!

عملية التنصيف - بصريًا

في البحث الثنائي، ننصّف مساحة البحث مع كل مقارنة. لنتتبّع ذلك خطوة بخطوة:

كيف يقلّص البحث الثنائي حجم المسألة

البداية
n عنصر
نبدأ بـ n عنصر للبحث فيها
1
n / 2 عنصر
بعد المقارنة الأولى نستبعد النصف. يتبقى n/2 فقط.
2
n / 4 = n / 22 عنصر
بعد المقارنة الثانية ننصّف مجددًا. يتبقى n/4 فقط.
3
n / 8 = n / 23 عنصر
بعد المقارنة الثالثة يتبقى n/8 فقط.
4
n / 16 = n / 24 عنصر
بعد المقارنة الرابعة يتبقى n/16 فقط.
k
n / 2k عنصر
النمط العام: بعد k مقارنة، يتبقى لدينا n / 2k عنصر!

متى نتوقف؟

ينتهي البحث عندما يتبقى عنصر واحد فقط:

n / 2k = 1

نحتاج الآن إلى إيجاد قيمة k (عدد الخطوات).

الاشتقاق الرياضي: إيجاد k

اشتقاق k = log2(n) خطوة بخطوة
1
n / 2k = 1
المعادلة الابتدائية: بعد k خطوة، يتبقى لدينا عنصر واحد.
2
2k · (n / 2k) = 1 · 2k
اضرب الطرفين في 2k: نضرب الطرفين الأيسر والأيمن في 2k للتخلّص من المقام.
قاعدة جبرية: إذا ضربنا طرفي المعادلة في القيمة نفسها، تبقى المعادلة متوازنة.
3
n = 2k
بسّط: في الطرف الأيسر، يُختصر 2k مع 2k في المقام، فيتبقى n. وفي الطرف الأيمن، 1 · 2k = 2k.
قاعدة الاختصار: (a/b) × b = a (يُختصر b)
4
log2(n) = log2(2k)
خذ اللوغاريتم للأساس 2 للطرفين: نستخدم اللوغاريتم للأساس 2 لأننا نقسم على 2 (ثنائي).
تعريف اللوغاريتم (Logarithm): إذا كان bx = y، فإن logb(y) = x
بعبارة أخرى: «لوغاريتم y للأساس b يسأل: إلى أي أسّ نرفع b لنحصل على y؟»
5
log2(n) = k × log2(2)
طبّق قاعدة القوة للوغاريتمات: ينزل الأسّ k ليصبح معاملًا مضروبًا.
قاعدة القوة (Power Rule): logb(xk) = k × logb(x)
تنص هذه القاعدة على أن: «لوغاريتم القوة يساوي الأسّ مضروبًا في لوغاريتم الأساس»
6
log2(n) = k × 1
بسّط log2(2): لوغاريتم 2 للأساس 2 يساوي 1.
قاعدة المطابقة (Identity Rule): logb(b) = 1
لماذا؟ لأن b1 = b. إذن «أي قوة للعدد b تعطي b؟» الإجابة هي 1.
7
k = log2(n)
النتيجة النهائية: عدد الخطوات k يساوي لوغاريتم n للأساس 2!
نقطة جوهرية

عدد الخطوات k اللازمة لتقليص n عنصر إلى عنصر واحد بالتنصيف المتكرر هو:

k = log2(n)

لذلك، يعمل البحث الثنائي في زمن O(log2n).

ملاحظة: في ترميز O الكبير، نكتب غالبًا O(log n) دون الأساس، لأن تغيير الأساس لا يغيّر إلا المعامل الثابت وليس معدل النمو. لكن في البحث الثنائي، الأساس هو 2 تحديدًا لأننا نقسم على 2!

لماذا الأساس 2؟ لأنه ثنائي!

العلاقة بكلمة «ثنائي» (Binary)

كلمة «ثنائي» تعني اثنين. في البحث الثنائي:

  • نقسم المصفوفة إلى جزأين
  • نحتفظ بجزء واحد ونستبعد جزءًا واحدًا
  • نقسم على 2 في كل خطوة

لهذا يكون أساس اللوغاريتم 2 - لأننا نُجري قسمة ثنائية (إلى اتجاهين)!

أمثلة عملية: كم عدد الخطوات؟

للبحث في مليار عنصر:

  • البحث الخطي: ما يصل إلى 1,000,000,000 مقارنة!
  • البحث الثنائي: نحو 30 مقارنة فقط!

هذه هي قوة O(log2n)!

المقايضة (Trade-Off)

البحث الثنائي أسرع بكثير، لكن:

  • يجب أن تكون البيانات مرتبة أولًا
  • الفرز (Sorting) يستغرق وقتًا (عادةً O(n log n))
  • يستحق ذلك إذا كنت ستبحث مرات عديدة في البيانات نفسها
