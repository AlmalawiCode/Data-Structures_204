1 · لماذا نحتاج إلى O(n log n)؟

درسنا في الفصل السابق خوارزميات الفرز التربيعية (Quadratic Sorting Algorithms) — الفرز بالاختيار (Selection Sort)، والفرز بالإدراج (Insertion Sort)، والفرز الفقاعي (Bubble Sort). إنها بسيطة ومفيدة تعليميًا، لكن تعقيدها O(n²) يجعلها غير عملية مع مجموعات البيانات الكبيرة.

O(n²)
تربيعي (Quadratic)

n = 1,000,000 → 1012 عملية
بطيئة جدًا على بيانات العالم الحقيقي

O(n log n)
لوغاريتمي (Logarithmic)

n = 1,000,000 → ~20,000,000 عملية
أسرع بـ 50,000× من O(n²)!

السؤال الأساسي: هل يمكننا الفرز بأسرع من O(n²)؟
الجواب: نعم — باستخدام فرّق تَسُد (Divide and Conquer). بدلًا من مقارنة كل عنصر (Element) بكل عنصر آخر، نقسم المسألة إلى نصفين في كل خطوة، ونحل كل نصف، ثم نجمع النتائج. وهذا يقلّل عدد المستويات إلى log₂(n).

استراتيجية فرّق تَسُد

  1. التقسيم (Divide) — جزّئ المسألة إلى مسائل فرعية أصغر
  2. الحل (Conquer) — حُلّ كل مسألة فرعية عوديًا (Recursively)
  3. الدمج (Combine) — ادمج حلول المسائل الفرعية في حل نهائي واحد
لماذا log n من المستويات؟ إذا قسمنا المصفوفة (Array) إلى النصف في كل خطوة، بدءًا من n عنصرًا: n → n/2 → n/4 → n/8 → … → 1. عدد المرات التي يمكننا فيها قسمة n على 2 قبل الوصول إلى 1 هو log₂(n). عندما n = 1,000,000، فهذا يعني نحو 20 مستوى فقط.

2 · نظرة عامة على الفصل

ندرس في هذا الفصل خوارزميتَي فرز بتعقيد O(n log n)، وكلتاهما قائمة على مبدأ فرّق تَسُد:

الفرز السريع (Quick Sort)

  • اختر عنصرًا ليكون المحور (Pivot)
  • التقسيم (Partition): العناصر < المحور تذهب إلى اليسار، والعناصر > المحور تذهب إلى اليمين
  • افرز كل قسم عوديًا
  • المتوسط O(n log n)، والأسوأ O(n²)
  • في الموضع نفسه (In-place) — لا يحتاج إلى مصفوفة إضافية

الفرز بالدمج (Merge Sort)

  • قسّم المصفوفة إلى نصفين
  • افرز كل نصف عوديًا
  • ادمج النصفين المفروزين في مصفوفة واحدة
  • دائمًا O(n log n) — مضمون
  • يحتاج إلى مساحة إضافية O(n)

علاقة التكرار — لماذا كلتاهما O(n log n)

تشترك الخوارزميتان في علاقة التكرار (Recurrence Relation) نفسها في الحالة المتوسطة/المعتادة:

T(n) = 2 · T(n2) + n

بالحل عن طريق التعويض (أو المبرهنة الرئيسية (Master Theorem)):

T(n) = n log₂ n  ∈  O(n log n)

في كل مستوى: عمل O(n). عدد المستويات: log₂(n). الإجمالي: O(n log n).

الآن رتّب كل مجموعة على حدة — فرّق تَسُد!

المجموعة اليسرى (4 طلاب) والمجموعة اليمنى (3 طلاب) مستقلتان تمامًا — لن تحتاجا إلى المقارنة ببعضهما مرة أخرى أبدًا، لأننا نعلم مسبقًا أن كل طالب في اليسار أقصر من كل طالب في اليمين.

طبّق فكرة المحور نفسها تمامًا عوديًا داخل كل مجموعة: اختر محورًا، واطلب من الجميع الانتقال إلى اليسار أو اليمين، وكرّر. كل مستوى من مستويات العودية (Recursion) يُجري على الأكثر n مقارنة في المجموع عبر جميع المجموعات في ذلك المستوى. ومع التقسيمات المتوازنة لا يوجد سوى log₂(8) = 3 مستويات:

3 مستويات × 8 مقارنات لكل مستوى = 24 مقارنة  مقابل  28 في الطريقة الساذجة  ←  O(n log n)

لـ 1,000,000 طالب: فقط ~20,000,000 مقارنة بدلًا من 500 مليار. أي أسرع بـ 25,000×!

!
التحدي الكبير: ماذا لو اخترت المحور الخطأ؟

ماذا لو اخترنا بدلًا من سارة (162 سم) هناء (145 سم) — أقصر طالبة؟ جميع الطلاب السبعة المتبقين أطول منها ← يذهبون جميعًا إلى اليمين. ويبقى الجانب الأيسر فارغًا. لم نصغّر المسألة إلا بطالب واحد فقط. ويتكرر هذا n مرة:

n مستوى × n مقارنة لكل مستوى = O(n²) — مثل الطريقة الساذجة تمامًا!

اختيار محور جيد هو التحدي المحوري في الفرز السريع. كيف تعثر بشكل موثوق على الطالب «الأوسط»؟ هذه مسألة بحثية نشطة في علوم الحاسب — تُسمّى مسألة اختيار المحور (Pivot Selection Problem) وما زالت تُدرس حتى اليوم.

هذا بالضبط ما يفعله الفرز السريع! فهو يختار عنصرًا محوريًا، ويقسّم كل ما هو أصغر إلى اليسار وكل ما هو أكبر إلى اليمين في تمريرة (Pass) واحدة، ثم يكرر العملية عوديًا على كل قسم. ورغم خطر الحالة الأسوأ، يُعد الفرز السريع أكثر خوارزميات الفرز استخدامًا في الواقع العملي بفضل سرعته الفائقة وأدائه الممتاز مع الذاكرة المخبئية (Cache).
الفكرة الأساسية: اختر عنصرًا ليكون المحور. أعد ترتيب (قسّم) المصفوفة بحيث يكون كل ما هو أصغر من المحور على اليسار وكل ما هو أكبر على اليمين. يصبح المحور الآن في موضعه النهائي الصحيح. ثم طبّق العملية نفسها عوديًا على كل نصف.

كيف تعمل — مخطط تقسيم هور (Hoare Partition Scheme)

  1. اختر عنصرًا محوريًا. يمكن اختيار المحور عشوائيًا، أو باستراتيجيات أخرى (الأول، الأخير، الوسيط من ثلاثة). في هذا الدرس نستخدم العنصر الأول A[l] محورًا.
  2. قسّم المصفوفة حول المحور:
    • المؤشر (Pointer) i يمسح من اليسار، باحثًا عن عناصر أكبر من المحور.
    • المؤشر j يمسح من اليمين، باحثًا عن عناصر أصغر من المحور أو مساوية له.
    • عندما يتوقف كلاهما، بدّل (Swap) A[i] وA[j].
    • عندما i ≥ j، ضع المحور في الموضع j — فهو الآن في موضعه النهائي المرتب.
  3. افرز عوديًا المصفوفة الجزئية (Subarray) اليسرى (الفهارس l … j−1) والمصفوفة الجزئية اليمنى (j+1 … h).
  4. الحالة الأساسية (Base Case): المصفوفة الجزئية ذات الحجم 0 أو 1 مرتبة أصلًا — توقف.

تحليل الخوارزمية

متوسط الحالة وأفضل حالة (Average Case & Best Case) — O(n log n):

كل عملية تقسيم تقسم المصفوفة إلى نصفين تقريبًا ← log₂(n) مستوى × عمل O(n) لكل مستوى

T(n) = 2 · T(n2) + n   →   O(n log n)

أسوأ حالة (Worst Case) — O(n²):

تحدث عندما يكون المحور دائمًا أصغر عنصر أو أكبر عنصر (مدخلات مرتبة أو مرتبة عكسيًا).

كل عملية تقسيم تنتج مصفوفة جزئية بحجم n−1 وأخرى بحجم 0 ← n مستوى ← عمل O(n) لكل منها

T(n) = T(n−1) + n   →   O(n²)

تجنّب الحالة الأسوأ: اختر محورًا عشوائيًا، أو استخدم استراتيجية الوسيط من ثلاثة (Median-of-Three) (خذ وسيط العناصر الأول والأوسط والأخير). في الواقع العملي، يكون الفرز السريع غالبًا أسرع الخوارزميات بفضل أدائه الممتاز مع الذاكرة المخبئية.

التنفيذ بلغة Java

الفرز السريع — مخطط تقسيم هور (Java)▼ 
// ═══════════════════════════════════════════════════════════════════════
//  PART 1 — quickSort   (the main recursive function)
//  Goal : sort the sub-array  A[l .. h]  in ascending order.
// ═══════════════════════════════════════════════════════════════════════
public static void quickSort(int[] A, int l, int h) {

    // Base case: if the sub-array has 0 or 1 element it is already sorted → stop.
    if (l < h) {

        // Partition the array and receive the pivot's final sorted position j.
        int j = partition(A, l, h);

        // Recursively sort the LEFT  partition → all elements smaller than the pivot.
        quickSort(A, l, j - 1);

        // Recursively sort the RIGHT partition → all elements greater than the pivot.
        quickSort(A, j + 1, h);
    }
}


// ═══════════════════════════════════════════════════════════════════════
//  PART 2 — partition   (Hoare Partition Scheme)
//  Goal : rearrange A[l..h] so that
//           A[l .. j]    contains elements  ≤ pivot   (left partition)
//           A[j+1 .. h]  contains elements  > pivot   (right partition)
//  Returns j — the pivot's final sorted index.
// ═══════════════════════════════════════════════════════════════════════
public static int partition(int[] A, int l, int h) {

    // ── Choose the pivot ─────────────────────────────────────────────────
    // Here we use the FIRST element A[l] as the pivot.
    // The pivot can also be chosen randomly or by other strategies.
    int pivot = A[l];

    // ── Set up the two pointers ──────────────────────────────────────────
    // i starts ONE STEP BEFORE the left boundary  → will scan to the RIGHT →
    // j starts ONE STEP AFTER  the right boundary → will scan to the LEFT  ←
    // Starting outside the range lets the do-while loops enter correctly.
    int i = l - 1;
    int j = h + 1;


    // ── Outer loop — repeat until i and j cross each other ───────────────
    while (i < j) {

        // ── MOVE i TO THE RIGHT  → ───────────────────────────────────────
        // Advance i one step at a time.
        //   • While A[i] <= pivot : this element is small enough — it BELONGS
        //     on the left side — keep moving right.
        //   • Stop  when  A[i]  > pivot : this element is TOO BIG for the left
        //     side — it is in the WRONG place and needs to move right.
        do {
            i++;
        } while (A[i] <= pivot);

        // ── MOVE j TO THE LEFT   ← ───────────────────────────────────────
        // Advance j one step at a time (moving leftward).
        //   • While A[j]  > pivot : this element is large enough — it BELONGS
        //     on the right side — keep moving left.
        //   • Stop  when  A[j] <= pivot : this element is TOO SMALL for the right
        //     side — it is in the WRONG place and needs to move left.
        do {
            j--;
        } while (A[j] > pivot);

        // ── SWAP if i has NOT yet crossed j ──────────────────────────────
        // Both pointers stopped on misplaced elements:
        //   A[i] is too BIG  (> pivot) but sits on the LEFT  side — wrong place.
        //   A[j] is too SMALL (≤ pivot) but sits on the RIGHT side — wrong place.
        // Swapping them corrects both elements in one move.
        //
        // If i >= j the pointers have CROSSED — partitioning is complete.
        // Do NOT swap — the loop condition (i < j) will exit on the next check.
        if (i < j) {
            swap(A, i, j);
        }

    } // ── end of outer while loop ──────────────────────────────────────────


    // ── Place the pivot in its final sorted position ─────────────────────
    // After the loop ends, j marks the boundary between the two partitions:
    //     A[l .. j]    → all ≤ pivot   (left partition)
    //     A[j+1 .. h]  → all  > pivot  (right partition)
    //
    // The pivot is still at A[l] (its original position).
    // Swap A[l] with A[j] to move the pivot to index j — the centre.
    // The pivot is now in its CORRECT FINAL SORTED POSITION.
    swap(A, l, j);

    // Return j so quickSort knows where to split for the two recursive calls.
    return j;
}


// ═══════════════════════════════════════════════════════════════════════
//  PART 3 — swap helper
//  Exchanges the values at positions i and j inside the array.
// ═══════════════════════════════════════════════════════════════════════
private static void swap(int[] A, int i, int j) {
    int temp = A[i];    // Step 1 — save A[i] in a temporary variable so we don't lose it
    A[i]      = A[j];   // Step 2 — overwrite A[i] with the value from A[j]
    A[j]      = temp;   // Step 3 — put the saved original value of A[i] into A[j]
}

فهم الشيفرة — خطوة بخطوة

P
اختيار المحور

pivot = A[l] — نختار العنصر الأول من المصفوفة الجزئية الحالية ليكون قيمة المحور. المحور هو العنصر الذي سينتهي به المطاف في موضعه النهائي المرتب الصحيح بعد استدعاء واحد لـ partition(). يمكن أيضًا اختيار قيمة المحور عشوائيًا — فآلية المؤشرين تعمل بالطريقة نفسها أيًّا كان العنصر المختار.

i →
تحريك المؤشر i إلى اليمين

i يبدأ عند l − 1 (خطوة واحدة قبل الحد الأيسر). والحلقة do { i++; } while (A[i] <= pivot) تدفعه نحو اليمين:

  • استمر ما دام A[i] ≤ pivot ← العنصر صغير بما يكفي، فهو ينتمي إلى اليسار.
  • توقف عندما A[i] > pivot ← وجدنا عنصرًا أكبر من اللازم للجانب الأيسر — يجب تبديله إلى اليمين.
← j
تحريك المؤشر j إلى اليسار

j يبدأ عند h + 1 (خطوة واحدة بعد الحد الأيمن). والحلقة do { j--; } while (A[j] > pivot) تدفعه نحو اليسار:

  • استمر ما دام A[j] > pivot ← العنصر كبير بما يكفي، فهو ينتمي إلى اليمين.
  • توقف عندما A[j] ≤ pivot ← وجدنا عنصرًا أصغر من اللازم للجانب الأيمن — يجب تبديله إلى اليسار.
↔
تبديل العنصرين الموضوعين في غير مكانهما

توقف كلا المؤشرين عند عنصرين في غير مكانهما. إذا كان i < j (لم يتقاطعا بعد)، نستدعي swap(A, i, j):

  • A[i] كان كبيرًا جدًا على الجانب الأيسر ← ينتقل إلى اليمين ✓
  • A[j] كان صغيرًا جدًا على الجانب الأيمن ← ينتقل إلى اليسار ✓

بعد التبديل، تتكرر الحلقة الخارجية while (i < j) — ويواصل i وj المسح من حيث توقفا حتى يجدا الزوج التالي من العناصر الموضوعة في غير مكانها.

i≥j
عندما i ≥ j — تقاطع المؤشران ← تنتهي الحلقة

عندما يصل i إلى j أو يتجاوزه، فهذا يعني أن كل عنصر قد فُحص:

  • الشرط if (i < j) يكون خاطئًا ← لا يحدث تبديل.
  • شرط الحلقة الخارجية while (i < j) يكون أيضًا خاطئًا ← تنتهي الحلقة.

أصبحت المصفوفة الآن مقسّمة: A[l..j] تضم كل العناصر ≤ المحور، وA[j+1..h] تضم كل العناصر > المحور. وأخيرًا ينقل swap(A, l, j) المحور من A[l] إلى A[j] — موضعه المرتب الصحيح إلى الأبد.

محاكاة خطوة بخطوة

افتح المحاكاة التفاعلية لاستكشاف خوارزمية التقسيم خطوة بخطوة. أدخل مصفوفة من اختيارك، واختر فهرس (Index) المحور، وشاهد مخطط هور أثناء العمل.

محاكاة تفاعلية — أدخل أي مصفوفة، واختر محورًا، وتتبّع كل عملية تبديل خطوة بخطوة.

▶ تشغيل محاكاة الفرز السريع

4 · الفرز بالدمج

الفكرة الأساسية: قسّم المصفوفة إلى نصفين، وافرز كل نصف عوديًا، ثم ادمج النصفين المفروزين في مصفوفة واحدة مفروزة. وعلى خلاف الفرز السريع، لا حاجة إلى محور أو تقسيم — فـ«العمل» كله يحدث أثناء خطوة الدمج.

لماذا يهم الفرز بالدمج — مشكلة البيانات الضخمة

طالب: «مهلًا — لدمج جزأين مفروزين حجم كل منهما 2 GB، ألا نحتاج إلى 4 GB من الذاكرة؟»

سؤال رائع! الجواب هو لا — وهذه هي الفكرة الجوهرية في الفرز بالدمج. لا تحتاج إلى وجود الملفين معًا في الذاكرة في الوقت نفسه. تفتح الملفين، وتقرأ عنصرًا واحدًا من كل منهما، وتقارن (Comparison) بينهما، وتكتب الأصغر في ملف الإخراج على القرص، ثم تقرأ العنصر التالي من الملف الذي جاء منه ذلك العنصر. في أي لحظة لا تحتفظ في الذاكرة إلا بـ عنصر واحد بالضبط من كل ملف.

تُكتب النتيجة المدموجة مباشرة إلى القرص، لا إلى مخزن مؤقت في الذاكرة. ويُسمّى هذا الفرز الخارجي (External Sorting) — والفرز بالدمج هو الخوارزمية المناسبة له على نحو فريد. وتستخدمه قواعد البيانات وأنظمة التشغيل وأطر الحوسبة الموزعة (مثل Hadoop وSpark) لفرز تيرابايتات من البيانات على عناقيد من الأجهزة.

العملية الأساسية في كل هذا: دمج تسلسلين مفروزين في تسلسل واحد مفروز. وبمجرد أن تتقن هذه المهارة الواحدة، ستفهم الخوارزمية وقوتها في العالم الحقيقي معًا.

الخطوة 0 — المهارة الأساسية: دمج مصفوفتين مفروزتين

قبل دراسة خوارزمية الفرز بالدمج العودية كاملة، دعنا نتقن خطوة الدمج وحدها. هذه هي مرحلة «الدمج» في فرّق تَسُد — حيث يحدث كل العمل الحقيقي في الفرز بالدمج.

المسألة: لدينا مصفوفتان مفروزتان، والمطلوب إنتاج مصفوفة واحدة مدموجة مفروزة.

اليسرى   L = [3, 9, 27, 56]
اليمنى R = [10, 38, 43, 82]

الناتج المتوقع: [3, 9, 10, 27, 38, 43, 56, 82]

خوارزمية المؤشرين (Two-Pointer Algorithm)

  1. ضع المؤشر i = 0 عند بداية المصفوفة اليسرى L.
  2. ضع المؤشر j = 0 عند بداية المصفوفة اليمنى R.
  3. ما دام كلا المؤشرين داخل مصفوفته:
    • إذا كان L[i] ≤ R[j]: انسخ L[i] إلى النتيجة، وقدّم i.
    • إذا كان L[i] > R[j]: انسخ R[j] إلى النتيجة، وقدّم j.
  4. عندما تنفد إحدى المصفوفتين، انسخ جميع العناصر المتبقية من الأخرى مباشرة إلى النتيجة.
لماذا تنجح هذه الطريقة: لأن المصفوفتين مفروزتان مسبقًا، فإن أصغر عنصر متبقٍّ على الإطلاق يكون دائمًا في مقدمة إحدى المصفوفتين — إما L[i] أو R[j]. ولا نحتاج أبدًا إلى البحث فيما وراء هذين الموضعين. مقارنة واحدة، ونسخ واحد، وتقديم مؤشر واحد. وهذا يمنحنا دمجًا بتعقيد O(n).

كيف تعمل — خوارزمية الفرز بالدمج كاملة

  1. التقسيم: أوجد نقطة المنتصف m = (l + h) / 2. وقسّم إلى A[l…m] وA[m+1…h].
  2. الحل: استدعِ mergeSort عوديًا على كل نصف.
  3. الحالة الأساسية: المصفوفة الجزئية ذات الحجم 1 (l == h) مرتبة أصلًا — ارجع فورًا.
  4. الدمج: استخدم مؤشرين: i (للنصف الأيسر) وj (للنصف الأيمن). قارن A[i] وA[j]، وانسخ الأصغر إلى مصفوفة مؤقتة B، وقدّم ذلك المؤشر. عندما ينفد أحد النصفين، انسخ ما تبقى من النصف الآخر. وأخيرًا انسخ B مرة أخرى إلى A.

تحليل الخوارزمية

جميع الحالات (الأفضل، المتوسطة، الأسوأ) — O(n log n):

يقسم الفرز بالدمج دائمًا إلى نصفين تمامًا ويدمج دائمًا جميع العناصر الـ n.

لا توجد حالة أسوأ — فالسلوك نفسه بغض النظر عن ترتيب المدخلات.

T(n) = 2 · T(n2) + n   →   O(n log n)

التعقيد المكاني (Space Complexity) — O(n):

تتطلب خطوة الدمج مصفوفة مؤقتة B بحجم n. وهذه هي المقايضة الرئيسية مقارنة بالفرز السريع (الذي يعمل في الموضع نفسه).

الميزة الأساسية: الفرز بالدمج فرز مستقر (Stable Sort) (تحتفظ العناصر المتساوية بترتيبها الأصلي) ويضمن O(n log n) حتى مع المدخلات المرتبة أو المرتبة عكسيًا أو المصممة لأسوأ أداء. وهو الخيار المفضل عندما يكون الأداء المضمون والاستقرار مطلوبين.

// Main recursive function
public static void mergeSort(int[] A, int l, int h) {
    if (l < h) {
        int m = (l + h) / 2;          // find midpoint
        mergeSort(A, l, m);            // sort left half
        mergeSort(A, m + 1, h);        // sort right half
        merge(A, l, m, h);             // merge sorted halves
    }
}

// Merge two sorted sub-arrays A[l..m] and A[m+1..h]
public static void merge(int[] A, int l, int m, int h) {
    int i = l, j = m + 1, k = l;
    int[] B = new int[A.length];      // temporary array

    while (i <= m && j <= h) {
        if (A[i] <= A[j]) {
            B[k++] = A[i++];           // take from left half
        } else {
            B[k++] = A[j++];           // take from right half
        }
    }
    while (i <= m)  B[k++] = A[i++];  // copy remaining left
    while (j <= h)  B[k++] = A[j++];  // copy remaining right

    for (int x = l; x <= h; x++) A[x] = B[x]; // copy back
}

محاكاة خطوة بخطوة

افتح المحاكاة التفاعلية لمشاهدة التنفيذ الكامل للفرز بالدمج على هيئة شجرة ثنائية (Binary Tree) — إذ تقسم مرحلة التقسيم الشجرة من الأعلى إلى الأسفل، وتعيد مرحلة الدمج بناءها من الأسفل إلى الأعلى.

تمثيل مرئي بالشجرة الثنائية — شاهد المصفوفة تنقسم مستوى بعد مستوى، ثم تُدمج من جديد مفروزة.
