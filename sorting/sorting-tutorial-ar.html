1 · الفرز بالاختيار (Selection Sort)

الفكرة الأساسية: نقسم المصفوفة (Array) إلى جزء مرتّب (على اليسار) و جزء غير مرتّب (على اليمين). في كل تمريرة (Pass)، نبحث عن أصغر (أو أكبر) عنصر (Element) في الجزء غير المرتّب وننقله إلى الحد الفاصل بين الجزأين.

كيف تعمل (ترتيب تصاعدي)

  1. نفترض أن العنصر الأول في الجزء غير المرتّب هو الأصغر.
  2. نفحص بقية الجزء غير المرتّب، ونحدّث الأصغر كلما وجدنا عنصرًا أصغر منه.
  3. بعد انتهاء الفحص، نبدّل (Swap) الأصغر الذي وجدناه مع العنصر الموجود عند الحد الفاصل.
  4. نحرّك الحد الفاصل خطوة واحدة إلى اليمين، ونكرر حتى تصبح المصفوفة كلها مرتّبة.

تحليل الخوارزمية — لماذا O(n²)؟

يستخدم الفرز بالاختيار حلقتين متداخلتين (Nested Loops). لنحسب بالضبط عدد المقارنات (Comparisons) التي يجريها:

الخطوة 1 — عدّ المقارنات في كل تمريرة:

T(n) = n + (n−1) + (n−2) + (n−3) + … + 3 + 2 + 1

التمريرة 1 تفحص n عنصرًا  |  التمريرة 2 تفحص n−1  |  …  |  التمريرة n تفحص عنصرًا واحدًا

اكتب المجموع مرة بالترتيب ومرة بالعكس، ثم اجمع عمودًا عمودًا — مجموع كل زوج يساوي (n+1)، وعدد الأزواج n:

T(n) =   1   +   2   +   3   + … + (n−1) +   n  
T(n) =   n   + (n−1) + (n−2) + … +   2   +   1  
2·T(n) = (n+1) + (n+1) + (n+1) + … + (n+1) + (n+1)

2 · T(n) = n × (n+1)    →   n من الأزواج، كلٌّ منها يساوي (n+1)

الخطوة 2 — نقسم الطرفين على 2:

T(n)  =  n  (n+1)2

الخطوة 3 — نفك البسط (إلى حدّين):

T(n)  =  n² + n2  =  12n²  +  12n

الحد المهيمن هو ½n²؛ أما الحد الأدنى رتبةً ½n فيمكن إهماله عندما تكون n كبيرة.

∴   T(n) ∈ O(n²)

نحذف الثابت ½ والحد الأدنى رتبةً ½n. لا يهمّنا إلا n².

مثال عملي — n = 6:

T(6) = 1 + 2 + 3 + 4 + 5 + 6
T(6) = 6 + 5 + 4 + 3 + 2 + 1
2·T(6) = 7 + 7 + 7 + 7 + 7 + 7

2 · T(6) = 6 × 7 = 42

T(6)  =  422  =  21 مقارنة  ✓

تحقّق:   n(n+1)2  =  6 × 72  =  422  =  21  ✓

مهم: يجري الفرز بالاختيار دائمًا عددًا ثابتًا من المقارنات يساوي n(n+1)/2 بالضبط، سواء كانت المصفوفة مرتّبة مسبقًا أو معكوسة تمامًا. قد يتغير عدد التبديلات (من 0 إلى n−1)، أما عدد المقارنات فلا يتغير أبدًا.
الفرز بالاختيار — الخصائص:
  • ينفّذ دائمًا العدد نفسه من المقارنات بغض النظر عن ترتيب المدخلات
  • غير تكيّفي (Not Adaptive) — لا يستفيد من البيانات المرتّبة جزئيًا
  • التعقيد الزمني (Time Complexity): O(n²) في جميع الحالات (أفضل حالة ومتوسط حالة وأسوأ حالة)
  • يتغير عدد التبديلات (من 0 إلى n−1)، لكن عدد المقارنات دائمًا n(n−1)/2 بالضبط

التنفيذ بلغة Java

الفرز بالاختيار — Java▼ 
public static void selectionSort(int[] arr) {
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {        // boundary position
        int minIdx = i;                            // assume min is at boundary
        for (int j = i + 1; j < n; j++) {        // scan unsorted part
            if (arr[j] < arr[minIdx]) {
                minIdx = j;                        // update min index
            }
        }
        if (minIdx != i) {                         // swap if needed
            int temp = arr[i];
            arr[i]      = arr[minIdx];
            arr[minIdx] = temp;
        }
    }
}

2 · الفرز بالإدراج (Insertion Sort)

الفكرة الأساسية: تشبه ترتيب أوراق اللعب في يدك. نبدأ بورقة واحدة (مرتّبة بطبيعتها). نأخذ الورقة التالية وندرجها في موضعها الصحيح بين الأوراق المرتّبة مسبقًا. ثم نكرر.

كيف تعمل (ترتيب تصاعدي)

  1. العنصر الأول وحده يشكّل مصفوفة جزئية (Subarray) مرتّبة حجمها 1 — وهي مرتّبة بطبيعتها!
  2. نأخذ العنصر التالي (ويُسمّى المفتاح (key)) من الجزء غير المرتّب.
  3. نقارن المفتاح بعناصر الجزء المرتّب، ماسحين من اليمين إلى اليسار.
  4. نزيح كل عنصر أكبر من المفتاح موضعًا واحدًا إلى اليمين.
  5. نضع المفتاح في الفراغ الناتج، فتكبر المصفوفة الجزئية المرتّبة بمقدار عنصر واحد.
  6. نكرر من الخطوة 2 حتى يتم إدراج جميع العناصر.

تحليل الخوارزمية

أفضل حالة (Best Case) (مصفوفة مرتّبة مسبقًا): O(n)

كل مفتاح في مكانه أصلًا ← الحلقة الداخلية تُنفَّذ 0 مرة ← المجموع n−1 مقارنة فقط

أسوأ حالة (Worst Case) (مصفوفة مرتّبة عكسيًا): O(n²)

T(n) = 1 + 2 + 3 + … + (n−1) = n(n−1)/2 — مثل الفرز بالاختيار تمامًا

متوسط الحالة (Average Case): O(n²)

ملاحظة جوهرية: يستطيع الفرز بالإدراج التوقف مبكرًا (الخروج من الحلقة الداخلية) بمجرد أن يجد الموضع الصحيح. وهذا يجعله أسرع بكثير من الفرز بالاختيار عندما تكون البيانات شبه مرتّبة!
الفرز بالإدراج — الخصائص:
  • تكيّفي بطبيعته (Naturally Adaptive) — لا يحتاج إلى أي علَم (flag) تحسين إضافي؛ فالحلقة الداخلية تتوقف فور العثور على الموضع
  • أفضل حالة: O(n) — المصفوفة مرتّبة مسبقًا؛ كل عنصر يحتاج إلى مقارنة واحدة فقط
  • أسوأ حالة: O(n²) — بيانات مرتّبة عكسيًا
  • عالي الكفاءة مع المصفوفات الصغيرة أو البيانات شبه المرتّبة؛ وغالبًا ما يتفوق عمليًا على كلٍّ من الفرز بالاختيار والفرز الفقاعي (Bubble Sort)

التنفيذ بلغة Java

الفرز بالإدراج — Java▼ 
public static void insertionSort(int[] arr) {
    int n = arr.length;
    for (int i = 1; i < n; i++) {
        int key = arr[i];         // element to be inserted
        int j   = i - 1;
        // shift elements greater than key to the right
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];   // shift right
            j--;
        }
        arr[j + 1] = key;          // insert key at correct position
    }
}

جرّب الضغط على التالي عندما يكون المفتاح هو 82 (العنصر الأخير في مصفوفتنا). لاحظ أنه تُجرى مقارنة واحدة فقط، ثم يتحرك الخط مباشرة إلى اليمين — دون أي تبديل.

لماذا؟ لأن كل ما على يسار الخط الفاصل مرتّب بشكل مضمون. والعنصر الأخير في الجزء المرتّب هو أكبر عناصره. فإذا كان المفتاح أكبر من هذا العنصر، فلا بد أنه أكبر من جميع العناصر المرتّبة — ولا حاجة إلى مقارنات إضافية.

حالة البيانات المقارنات لكل مفتاح إجمالي المقارنات
مرتّبة كليًا — كل مفتاح في مكانه أصلًا 1 لكل مفتاح n − 1 → O(n)
شبه مرتّبة — معظم المفاتيح تحتاج إلى خطوات قليلة 1 – 3 لكل مفتاح قريب من O(n)
مرتّبة عكسيًا — كل مفتاح يمشي حتى الموضع 0 i لكل مفتاح n(n−1)/2 → O(n²)

الخلاصة: يجري الفرز بالاختيار دائمًا n(n−1)/2 مقارنة بالضبط أيًّا كان شكل البيانات. أما الفرز بالإدراج فيتكيّف — ففي البيانات شبه المرتّبة قد يكون أسرع بفارق كبير. وهذه هي أعظم نقاط قوته.

3 · الفرز الفقاعي (Bubble Sort)

الفكرة الأساسية: نقارن كل زوج من العناصر المتجاورة ونبدّلهما إن كانا بترتيب خاطئ. بعد كل تمريرة، يكون أكبر عنصر غير مرتّب قد "طفا" إلى موضعه الصحيح في النهاية.

الجزء أ — الفرز الفقاعي الأساسي

في صورته الأساسية، ينفّذ الفرز الفقاعي جميع التمريرات الـ n−1 بغض النظر عن ترتيب المدخلات:

  1. نبدأ من أول المصفوفة.
  2. نقارن كل زوج متجاور (arr[j], arr[j+1]). إذا كان arr[j] > arr[j+1] نبدّلهما.
  3. بعد تمريرة كاملة واحدة، يكون أكبر عنصر قد "طفا" إلى الموضع الأخير — أي في مكانه الصحيح.
  4. نكرر لجميع التمريرات الـ n−1 — ينفّذ كل التمريرات دائمًا، حتى لو كانت المصفوفة مرتّبة مسبقًا.
الفرز الفقاعي الأساسي — الخصائص:
  • التعقيد الزمني: O(n²) في جميع الحالات — ينفّذ دائمًا جميع التمريرات الـ n−1
  • غير تكيّفي — لا يستطيع اكتشاف أن المصفوفة مرتّبة مسبقًا
  • مطابق للفرز بالاختيار في الأداء: كلاهما يجري دائمًا n(n−1)/2 مقارنة بالضبط

الجزء ب — الفرز الفقاعي المحسَّن (الخروج المبكر)

علَمٌ واحد من النوع المنطقي (boolean flag) (swapped) يحوّل الفرز الفقاعي إلى خوارزمية تكيّفية — ويُعدّ هذا "تحسينًا ذكيًا":

  1. في بداية كل تمريرة، نضبط swapped = false.
  2. إذا حدث أي تبديل أثناء التمريرة، نضبط swapped = true.
  3. بعد التمريرة: إذا كان swapped == false، فلا توجد عناصر في غير ترتيبها ← المصفوفة مرتّبة مسبقًا ← نتوقف فورًا.
الفرز الفقاعي المحسَّن — الخصائص:
  • تكيّفي: نعم — فحص "عدم وجود تبديلات" يكتشف البيانات المرتّبة ويخرج مبكرًا
  • أفضل حالة: O(n) — البيانات المرتّبة مسبقًا تؤدي إلى الخروج المبكر بعد تمريرة واحدة فقط
  • أسوأ حالة: O(n²) — بيانات مرتّبة عكسيًا (مثل النسخة الأساسية)
لماذا يُسمّى "الفرز الفقاعي"؟
راقب المحاكاة: في كل تمريرة، "يطفو" أكبر عنصر متبقٍّ إلى الطرف الأيمن، كفقاعة تصعد عبر الماء — فهو يستمر في التبديل مع جاره الأيمن حتى يصل إلى السطح (موضعه الصحيح).

تحليل الخوارزمية

أسوأ حالة: O(n²)

مدخلات مرتّبة عكسيًا — كل زوج يحتاج إلى تبديل في كل تمريرة

T(n) = (n−1) + (n−2) + … + 1 = n(n−1)/2

أفضل حالة (مع تحسين الخروج المبكر): O(n)

مرتّبة مسبقًا — التمريرة الأولى لا تجد أي تبديل ← يتوقف فورًا بعد n−1 مقارنة

الفرز الفقاعي المحسَّن: توجد نسخة معروفة تضيف علَم swapped — فإذا اكتملت تمريرة كاملة دون أي تبديل، تكون المصفوفة مرتّبة مسبقًا وتنتهي الخوارزمية فورًا، مما يعطي O(n) في أفضل حالة. وإذا أردت التعمق أكثر، فابحث على الإنترنت عن "optimized bubble sort".

التنفيذ بلغة Java

الفرز الفقاعي — Java (مع تحسين الخروج المبكر)▼ 
public static void bubbleSort(int[] arr) {
    int n = arr.length;
    for (int pass = 0; pass < n - 1; pass++) {
        boolean swapped = false;
        for (int j = 0; j < n - 1 - pass; j++) {
            if (arr[j] > arr[j + 1]) {
                int temp  = arr[j];
                arr[j]     = arr[j + 1];
                arr[j + 1] = temp;
                swapped = true;
            }
        }
        if (!swapped) break;  // already sorted — early exit
    }
}

4 · الفرز بالإدراج مقابل الفرز بالاختيار — هل تؤثر البيانات؟

يسأل طالب: "يا أستاذ، إذا كان كلٌّ من الفرز بالاختيار والفرز بالإدراج O(n²)، فأيهما أسرع فعليًا؟"

يجيب الأستاذ: "سؤال ممتاز! لهما التعقيد نفسه في أسوأ حالة، لكن عمليًا قد يكون الفرز بالإدراج أسرع بكثير عندما تكون البيانات شبه مرتّبة. دعني أريك السبب."

الفرق الجوهري

الفرز بالاختيار

يفحص دائمًا كامل الجزء غير المرتّب المتبقي ليجد الأصغر.
عدد المقارنات = n(n−1)/2، بغض النظر عن المدخلات.

الفرز بالإدراج

يستطيع التوقف مبكرًا بمجرد العثور على موضع الإدراج الصحيح.
في البيانات شبه المرتّبة، يتوقف كل مفتاح تقريبًا بعد 1–2 مقارنة فقط!

مقارنة على 5 مجموعات بيانات مختلفة (8 عناصر، ترتيب تصاعدي)

⚠️ ملاحظة مهمة قبل قراءة الجدول

الفرز الفقاعي الأساسي (دون فحص الخروج المبكر) يجري دائمًا n(n−1)/2 = 28 مقارنة بالضبط عندما n=8، بغض النظر عن البيانات — مطابقًا للفرز بالاختيار. فلا سبيل له لاكتشاف أن المصفوفة مرتّبة مسبقًا.

يستخدم الجدول أدناه الفرز الفقاعي المحسَّن — النسخة التي تتضمن فحص الخروج المبكر (if no swaps in a pass → stop). وهي النسخة التي يشرحها هذا الفصل وتظهر في المحاكاة أعلاه. ولا يظهر الفرق إلا عندما تكون البيانات شبه مرتّبة أو مرتّبة كليًا.

اضغط الزر أدناه لتشغيل الخوارزميات الثلاث على كل مجموعة بيانات وعدّ المقارنات.

    • الفرز بالإدراج — تكيّفي بطبيعته دون أي حيلة إضافية. أفضل حالة O(n). وغالبًا ما يكون الخيار الأفضل بين هذه الثلاث للبيانات الواقعية.
